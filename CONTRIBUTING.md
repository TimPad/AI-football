# Разработка

Используйте [локальный запуск](README.md#локальный-запуск) и зависимости из `uv.lock` / `web/package-lock.json`. Для разработки нужны extras `dev`, `web`, `web-dev`; `uv sync --locked --all-extras` устанавливает их вместе.

## Изменения

- Делайте ветки `codex/<описание>` или отдельную рабочую ветку; описывайте в PR проблему, итоговое поведение и проверки.
- Изменения схемы БД сопровождайте новой миграцией Alembic; уже применённые миграции не переписывайте.
- После изменения API экспортируйте OpenAPI и обновляйте `web/src/api/types.ts` командами из README.
- Протокол и CV-аналитика — независимые источники. Не изменяйте счёт/голы/карточки по импортированным CV-данным.
- Личность человека определяется UUID игрока. Номер, имя и track_id не заменяют UUID.
- Подтверждённые версии сохраняются; повторы команд не должны удваивать записи. Неизвестная метрика остаётся `null` с причиной.
- Тесты БД запускаются только на выделенных тестовых базах; рабочие данные не очищаются.

## Оформление и линтер

Код оформляют инструменты, а не руки: Python — `ruff` (настройки в `pyproject.toml`), интерфейс — Biome (`web/biome.jsonc`). Строка до 120 символов, одинарные кавычки. CI падает на неотформатированном файле и на любом замечании уровня ошибки.

```sh
.venv/bin/ruff format src tests scripts migrations      # оформить Python
.venv/bin/ruff check --fix src tests scripts migrations  # замечания; безопасные исправятся сами
npm --prefix web run format                              # оформить интерфейс и применить безопасные исправления
npm --prefix web run lint                                # то же, что проверяет CI
```

- `web/src/api/types.ts` создаётся из OpenAPI и из оформления исключён.
- После `ruff check --fix` запускайте тесты: исправление `UP007` однажды заменило `Union[tuple(...)]` на кортеж и сломало сборку схем. Такие места помечены `noqa` с причиной.
- Часть правил пока отключена или переведена в предупреждения — это известный долг с подсчётом в комментариях обоих конфигов (типы кнопок, зависимости эффектов, доступность, `zip` без `strict`). Новые правила в список не добавляйте; закрыли класс замечаний — уберите его строку.
- Фикстуры pytest, импортируемые из другого тестового модуля, помечайте `# noqa: F401`, иначе линтер сочтёт импорт лишним.

## Проверка перед публикацией

```sh
.venv/bin/ruff check src tests scripts migrations
.venv/bin/ruff format --check src tests scripts migrations
npm --prefix web run lint
.venv/bin/python -m pytest --tb=line -q
npm --prefix web run test
npm --prefix web run build
npm --prefix web run test:e2e
git diff --check
```

Для E2E заранее установите Chromium. По умолчанию используется 8181; занятый сервис не останавливайте. Изолированный запуск: `AIF_E2E_PORT=8283 AIF_E2E_DATABASE_NAME=aifootball_ux_e2e AIF_WEB_DIST=<абсолютная папка сборки> npm --prefix web run test:e2e`. База должна оканчиваться на `_e2e`: тестовый launcher очищает только её. Для синтетических сценариев капитана и адресов добавьте `AIF_E2E_FAKE_MAIL=1 AIF_E2E_FAKE_ADDRESS=1`; реальная почта и Яндекс при этом не вызываются. Если на этой же машине работает сервис организатора, не пересобирайте общую `web/dist`: соберите ветку отдельно (`npx --prefix web vite build --outDir <папка>`) и запустите тестовый сервис с `AIF_WEB_DIST=<папка>`, затем E2E с `AIF_REUSE_E2E=1`. Реальное видео и веса моделей нужны только для отдельной CV-приёмки, не для обычного CI.

Не добавляйте `.env`, cookies/токены, исходные записи, фото участников, модели, базы, backup, ZIP результатов и локальные снимки экрана. Для воспроизводимых проверок используйте синтетические fixtures. Новые ограничения и изменения пользовательского сценария отражайте в документации.
