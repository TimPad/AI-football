# Внешняя обработка видео и импорт отчёта

Статус: первая поставка реализована 14 октября 2026. [Инструкция и фактическая приёмка](../2026-10-14-analysis-stage1.md). Локальная связанная программа и облачный режим остаются последующими этапами; спортивная точность и реальные личности требуют отдельной проверки.

План внедрения: [задачи и приёмка](../superpowers/plans/2026-10-13-video-analytics-import.md). Архитектура: [интерактивная HTML-схема](../architecture/2026-10-13-video-analytics.html).

## 1. Что получаем на первом этапе

Оператор обрабатывает видео на своём компьютере или передаёт его внешнему исполнителю. В карточку матча загружается пакет результатов. Сайт проверяет пакет, показывает аналитику, помогает привязать видеотреки к людям и сохраняет подтверждённую индивидуальную статистику. Видеофайл остаётся у оператора; веб-серверу не нужны GPU, S3 для оригиналов или постоянно доступный компьютер обработчика.

Первый поддерживаемый источник — существующий Python CLI проекта. Другой внешний обработчик может создавать пакет по той же опубликованной схеме. Скан/PDF сам по себе становится документом матча; он не превращается автоматически в структурированную статистику. Для чисел нужен JSON или ручное заполнение таблицы. Автоматическое извлечение показателей из произвольных PDF не входит в этот этап.

## 2. Пользовательский путь

1. Пользователь с правом **Админ+ / управление аналитикой** открывает матч → **Видео и аналитика**.
2. Выбирает профиль камеры, подтверждает составы, сопоставляет распознанные команды A/B с хозяевами/гостями, задаёт интервалы матча в записи, если они известны. Создаёт пакет задания.
3. **Скачать задание для обработки**: ZIP с идентификатором задания/матча, снимками составов и геометрии, файлами текущей CV-конфигурации. Для вычисления отдельной метрики может потребоваться указанный в задании параметр обработки; конфигурация и её версии сохраняются.
4. На компьютере оператора: указать локальное видео, запустить обработчик с пакетом задания. Первоначально это одна команда CLI с прогрессом в терминале; запускать произвольный Python нажатием обычной кнопки сайта не предполагается. Интервалы можно уточнить при обработке, сохранив их в результате.
5. Обработчик создаёт **пакет результатов** с JSON, миниатюрами и метаданными. Оператор возвращается в тот же матч → **Загрузить результаты**.
6. Сайт проверяет принадлежность матчу/заданию, формат, геометрию и целостность, показывает предварительный отчёт. Загруженный пакет имеет статус **На проверке**, ещё не участвует в подтверждённой истории игроков.
7. Оператор подтверждает стороны A/B и сопоставляет обнаруженные фрагменты с игроками состава. Номер на форме и миниатюра помогают ручному выбору; автоматического OCR в первой поставке нет.
8. **Подтвердить аналитику** фиксирует назначения, сохраняет индивидуальные показатели и выбирает эту версию активной. Отдельное **Опубликовать** открывает выбранные данные зрителям. Ручной протокол остаётся самостоятельным источником счёта/голов/карточек.

Создание задания не означает, что видео уже обрабатывается. При ручном варианте сайт может показывать **Ожидает внешней обработки**, **Результат загружен**, **На проверке**, **Подтверждён**. Реальный автоматический прогресс появляется только с подключённым локальным обработчиком. Сообщение «обработка завершена» подтверждается принятым результатом, а не нажатием кнопки.

## 3. Права Админ+

Реализовано отдельное capability `can_manage_analytics`, отображаемое в интерфейсе как **Админ+**. Не выдавать его автоматически всем существующим администраторам. Первое назначение — владельцем установки через административную команду; дальнейшее управление правом — отдельная явно разрешённая операция.

| Действие | Админ | Админ+ | Зритель |
|---|---|---|---|
| Турниры, команды, расписание, ручной протокол | Да | Да | Нет |
| Смотреть внутренний отчёт | Да | Да | Нет |
| Создавать задания, импортировать результаты, назначать личности | Нет | Да | Нет |
| Подтверждать/переключать/публиковать версию аналитики | Нет | Да | Нет |
| Смотреть опубликованные показатели | Да | Да | Да |

API проверяет право на каждую операцию; скрытая кнопка не служит проверкой. Подтверждение аналитики не требует заново открывать подтверждённый ручной протокол. Если изменён состав, результаты должны быть проверены относительно нужного исторического снимка; несогласованное назначение блокируется.

## 4. Формат обмена

Задание выдаёт сервер. Предлагаемые файлы:

```text
job.zip
  job.json          # contract_version, job_id, match_id, context_hash
                    # UUID команд, снимок составов/номеров и камеры,
                    # параметры, ожидаемые единицы измерения
  venue.yaml
  homography.json
  pitch_polygon.json
  calib.json        # при наличии коррекции объектива

result.zip
  manifest.json     # версия контракта, job_id/match_id/context_hash,
                    # run_id, SHA256 видео, длительность/разрешение,
                    # версия обработчика/моделей, список файлов/хешей
  report.json       # структурированная аналитика по матчу и таймам
  track-index.json  # список фрагментов, команды, интервалы наблюдений
  thumbs/           # изображения для проверки личности
  checks.json       # качество/полнота обработки
```

Оригинальное видео в ZIP не нужно. Хеш видео вычисляет внешний обработчик: это идентификатор заявленного источника, а не доказательство его подлинности без доступа сервера к оригиналу. По желанию сохраняется ссылка на доступную запись для ручной проверки. В миниатюрах нужен реальный кадр, а не только координаты требуемого кадра.

В текущем `report.json` есть `schema_version=1`, команды, периоды и игроки с `track_id`, `observed_s`, `distance_m`, `m_per_min`, `hsr_m`, `sprints`, `vmax_ms`, `heatmap_s`. **Нет** `match_id`, `player_id`, уникального прогона и гарантированной привязки к сохранённой камере. Нужна команда упаковки, которая добавит манифест, интервалы наблюдений и изображения из артефактов/исходника. Текущий JSON не следует считать готовым контрактом импорта.

Для старых отчётов без задания возможен отдельный явно помеченный импорт: оператор вручную выбирает матч, стороны, геометрию и подтверждает происхождение. Такой отчёт не получает статус автоматически проверенной совместимости. Для первой поставки предпочтителен пакет, созданный из выданного задания.

HTML/PDF можно приложить для скачивания. Статистику и графики сайт строит из проверенного JSON собственными компонентами; загруженный произвольный HTML не исполняется в кабинете.

## 5. Отчёт и связь с игроками

Вкладка содержит обзор команд, показатели матча/таймов, тепловые карты и таблицу идентификации:

| Миниатюра | Команда | Наблюдаемые интервалы | Игрок состава | Состояние |
|---|---|---|---|---|
| Кадр фрагмента 17 | Хозяева | 03:12–04:40 | №7 Иван Петров | Подтверждён |
| Кадр фрагмента 42 | Хозяева | 08:10–09:05 | №7 Иван Петров | Подтверждён |
| Кадр фрагмента 53 | Гости | 08:15–08:50 | Не определён | Без привязки |

Несколько непересекающихся фрагментов одного человека объединяются в одну строку за матч. Дистанция, время наблюдения, HSR и количество спринтов суммируются; средние показатели рассчитываются по соответствующим суммам, а не среднему от средних. Максимальная устойчивая скорость берётся как максимум, тепловые карты суммируются в общей метрической ориентации. Не складывать «весь матч» и его же таймы: основной период обозначен отдельно, таймы — разрезы тех же данных.

Пересекающиеся назначения одного человека требуют исключить дубль либо пересчитать источник. Без разрешения конфликта нельзя подтвердить индивидуальную статистику. Через разрыв между фрагментами не добавляются расстояние и скорость. Неизвестные треки остаются в предварительном отчёте и не попадают в карточку конкретного человека.

Первый импорт работает с целыми проверенными фрагментами. Если внутри трека сменился человек, оператору нужно разделить/исправить его в обработчике и выгрузить новую версию. Произвольное разделение уже посчитанных агрегатов в кабинете невозможно без исходных временных рядов. Полноценная редактура интервалов и пересчёт по сырому треку — следующий этап общей архитектуры.

Короткие фрагменты текущий отчёт отфильтровывает из таблицы игроков; упаковщик должен сохранять их в индексе проверки, даже если показатель для них пока недоступен. У каждого назначения есть стабильный `player_id`, сторона, исторические имя/номер и список исходных фрагментов. Имя или номер сами по себе не являются ключом.

Наблюдаемое время обозначается **Время в анализируемом видео**. Оно не подменяет игровое время на площадке. Частичная запись, неизвестный показатель и экспериментальная метрика имеют явные отметки; неизвестное не записывается нулём. Ненадёжные автоматические передачи/владение не заменяют подтверждённые ручные события.

## 6. Хранение и целостность

Минимальная основа:

- `analysis_jobs`: выданное задание, матч, снимок контекста, автор и дата.
- `analysis_runs`: импортированный неизменяемый пакет, идентификатор/хеш источника, параметры/версии, статус проверки, автор, хеш содержимого.
- `analysis_assignments`: назначения фрагментов людям и ревизия ручной проверки.
- `player_match_metrics`: `match_id + player_id + версия аналитики`, показатели и происхождение.
- Матч хранит указатель на активную подтверждённую и отдельно опубликованную версии. Файлы хранятся в отдельной приватной папке сервера вместе с резервной копией; позднее хранилище можно заменить на S3.

Повтор загрузки того же пакета возвращает уже импортированный прогон. Повтор подтверждения не создаёт ещё одну строку игрока за матч. Перезагрузка страницы и потеря ответа не меняют ключ команды. Новая обработка создаёт новую версию; сезонные итоги используют только активный подтверждённый прогон каждого матча. Предыдущие файлы/назначения сохраняются.

Импорт целиком проверяется до переключения активной версии: правильный матч/задание, совпадение снимка камеры/составов, единицы, конечные числовые значения и разумные диапазоны, периоды/временные интервалы, размеры тепловых карт, ссылки на треки, хеши и объём файлов. ZIP читается с ограничением распакованного размера/числа файлов; вложенные архивы, исполняемые файлы, ссылки и пути за пределами каталога отклоняются. Ошибка оставляет предыдущую подтверждённую статистику доступной.

Общие правки даты/судей не делают корректный пакет недействительным. Для совместимости сравниваются значимые снимки геометрии и составов, а не любая изменившаяся ревизия матча. Изменение личности/назначений проходит отдельную проверку перед новым подтверждением.

## 7. Запуск с сайта на своём компьютере — второй шаг

После работающего импорта можно добавить небольшую установленную локальную программу **AI Football Processor**. Оператор подключает её к кабинету, выбирает локальную запись и запускает только назначенные задачи. Встроенного в браузер запуска CLI не требуется.

Программа сама обращается к серверу по HTTPS: получает задание, сообщает этапы/прогресс, передаёт результат по тому же контракту. Подключение выдаёт ограниченные, отзывные полномочия конкретного оператора/задач; пароль администратора и прямой доступ к БД не нужны. Команды выполняются только после локального подтверждения оператора; пакет задания содержит данные, а не произвольный shell-код.

В кабинете появляется **Обработать на моём компьютере** при подключённом обработчике. Оператор выбирает файл в локальной программе. Браузерный путь к выбранному файлу не считается действительным путём на диске программы. Если компьютер выключен, задача ждёт; неудавшийся запуск не отмечается завершённым. Для первой версии программы достаточно запуска по запросу, без общей распределённой очереди.

Сайт и компьютер обработки могут быть разными машинами. Если сам сайт пока живёт на `127.0.0.1`, другой компьютер не сможет подключиться к нему по этому адресу: потребуется доступный адрес в локальной сети или отдельное размещение. Ручной перенос ZIP позволяет начать без такой связности.

## 8. Порядок поставки и приёмка

**Первая полезная поставка:** право Админ+, пакет задания/результата, импорт/предпросмотр, подтверждение A/B и личностей, показатели в карточке матча и история игрока, версии без дублей. Без OCR и без новой сегментационной модели можно проверить весь путь на текущем детекторе/трекере с ручными назначениями.

**Вторая поставка:** локальная программа и прогресс из кабинета, автоматическая обратная загрузка того же пакета.

**Дальнейшие поставки:** маски сегментации, OCR, редактура интервалов с пересчётом, облачные обработчики. Контракт обмена и страницы отчёта переиспользуются.

Приёмка первой поставки: один реальный матч обрабатывается вне сайта, импортируется, связывается с составами и появляется в истории игроков. Повтор импорта не удваивает метрики; отчёт другого матча и конфликтующие фрагменты отклоняются; обычный администратор не может изменять аналитику; новая версия не увеличивает число сыгранных матчей; восстановление БД/файлов сохраняет те же цифры и назначения.
