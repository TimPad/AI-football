# Залы, расписание и координаты CV — 13 октября 2026

Реализованы справочник залов, обязательный выбор зала для новых матчей, снимок геометрии матча и неизменяемые версии калибровок камеры. Миграция `0007_halls` сохраняет существующие матчи: они могут остаться с прежним текстовым местом проведения до назначения зала. Редактирование даты, судей и трансляции таких матчей остаётся доступным без принудительной привязки.

## Работа организатора

1. Кабинет → **Залы → Создать зал**. Обязательны название, адрес, точная длина и ширина игровой площадки между линиями разметки в метрах. Дополнительно: покрытие, высота потолка, описание. Всё вводится вручную. Полей GPS в форме нет; ссылка «Открыть в Яндекс Картах» ищет введённый адрес.
2. В расписании при создании матча выбрать **Зал**. Название, адрес и размеры сохраняются снимком. Последующая правка справочника не меняет старые матчи и опубликованные протоколы.
3. Карточка зала → **Добавить профиль камеры**. Указать имя камеры, разрешение исходного кадра и минимум четыре соответствия пиксель → метры. Первые четыре строки по умолчанию предполагают углы поля в порядке обхода. Если углы не видны, можно ввести другие известные точки разметки и отдельно задать видимый контур в дополнительных настройках.
4. Матч → **Информация → Профиль камеры**: выбрать версию и сохранить. Для назначения матча профиль необязателен; для выгрузки CV-конфигурации обязателен.
5. **Скачать координаты для CV** выгружает ZIP для существующего CLI.

Формы зала и камеры сохраняют ввод в локальном черновике. Кнопка «Обновить залы и камеры» в форме матча подхватывает записи из другой вкладки, сохраняя текущий ввод. Повторная отправка после потерянного или оборванного ответа использует тот же ключ и не создаёт дубль. Конфликт версии возвращает 409, а не перезаписывает более свежую запись.

## Системы координат

| Данные | Назначение |
|---|---|
| X/Y поля в метрах | Траектории, расстояния, скорости, тепловые карты |
| X/Y исходного кадра в пикселях | Привязка конкретной камеры к плоскости поля |

Начало координат поля — выбранный угол; X направлена вдоль длины, Y вдоль ширины. В кадре X идёт вправо, Y вниз. Для разных камер одного зала нужны отдельные профили. При сдвиге камеры, зуме, кадрировании или изменении разрешения нужна новая версия. Одной статической гомографии недостаточно для движущейся камеры.

Профиль содержит реальные размеры поля, разрешение, точки, контур, гомографию, опциональную коррекцию объектива `K/dist` и оценки ошибки в метрах. Проверяются границы кадра/поля, повторяющиеся и вырожденные точки, самопересечение контура, конечность и обратимость преобразования, отсутствие разрыва внутри области поля. Для более четырёх точек показывается ошибка с исключением точки. Четыре точки могут дать нулевую ошибку подгонки; это не гарантия физической точности. Оценки предназначены для ручной проверки, автоматического порога качества пока нет.

Изменение размеров зала не меняет старую калибровку. Новому матчу можно назначить только профиль, совпадающий с его размерами. Старый матч продолжает использовать подходящую прежнюю версию. При выборе другого зала профиль сбрасывается. Архивные залы нельзя назначать новым матчам; существующие ссылки сохраняются.

## Использование в обработчике

ZIP содержит `venue.yaml` (UUID зала, измеренные размеры, настройки обработки, ожидаемое разрешение, UUID профиля), `homography.json` (H, точки и ошибки), `pitch_polygon.json` (контур), `source.json` (UUID матча, снимок зала, UUID/версия профиля), а также `calib.json`, если задана коррекция объектива.

Распаковать архив в отдельную папку и запустить:

```sh
.venv/bin/python -m aifootball.cli run \
  --video /absolute/path/match.mp4 \
  --venue /absolute/path/unpacked-cv-config \
  --match /absolute/path/output-match \
  --models /absolute/path/models
```

В папке моделей должны быть веса из `venue.yaml` (по умолчанию `yolo11m.pt`). Параметры детектора можно изменить перед запуском. Размеры поля берутся из измерений зала, а не нормативных размеров регламента. Декодирование проверяет совпадение разрешения видео с профилем. В `meta.json` записываются UUID зала и профиля, ожидаемый размер кадра.

Экспорт и серверные профили приватны. На публичной странице матча показаны название, адрес и размеры зала. Сетка расписания группирует площадки по UUID: одноимённые залы не объединяются.

Загрузка видео в S3, очередь GPU-обработки и запись индивидуальных результатов в БД остаются следующим этапом, описанным в [проекте аналитики](specs/2026-10-13-player-match-analytics-design.md) и [вариантах загрузки и воркеров](specs/2026-10-13-video-upload-and-workers-options.md). Здесь готова связь геометрии базы данных с действующим CV-обработчиком через экспорт.

## Контракты и проверка

- `/api/v1/halls`: приватный список и идемпотентное создание; `GET/PUT /halls/{id}` — карточка и изменение с `expected_revision`.
- `/halls/{id}/camera-profiles`: список и создание неизменяемой версии с `expected_hall_revision`.
- Матч: `hall_id`, `hall_snapshot`, `camera_profile_id`; выбор меняется через обычный журнал команд `update_match`.
- `GET /api/v1/matches/{id}/cv-config`: приватный детерминированный ZIP; без профиля — 422.
- Резервное восстановление сверяет залы, команды сохранения, камеры и ссылки/снимки матчей.

Серверные тесты проверяют ревизии, геометрию, версии, приватность, стабильность ZIP и реальный `load_venue → project_tracks` с измеренными размерами. UI-проверка защищает сетку от объединения одноимённых залов. Сквозной браузерный сценарий проверяет формы, черновик, потерю ответа камеры, повтор без дубля, привязку к матчу, скачивание ZIP и сохранение исторической геометрии. Выполняется визуальная проверка ширин 1440/768/375. Обработка нового реального видеоматча в этом этапе не запускалась.

Итоговая проверка: 299 серверных тестов прошли, 1 исключён штатной конфигурацией; 22 UI-проверки; 7 сквозных Chromium-сценариев; сборка TypeScript/Vite и восстановление наполненной резервной копии успешны.

По уточнению пользователя географические поля убраны из формы. Яндекс Карты открываются по адресу из карточки зала или сохранённого снимка матча. Формат адресной ссылки соответствует [документации Яндекса](https://yandex.com/dev/yandex-apps-launch-maps/doc/en/concepts/yandexmaps-web). Старые необязательные поля API сохраняются для совместимости уже отправленных черновиков; CV использует только размеры и калибровку поля.

После удаления полей GPS проверены 22 UI-теста, сборка и два затронутых сквозных сценария (залы и публичный календарь).
