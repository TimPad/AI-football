# Этап 1: внешняя обработка и импорт аналитики

Реализован 14 октября 2026. Локальный сервис обновлён до `0009_analysis_revision`. Оригинал видео остаётся у оператора. Сайт принимает структурированный ZIP, показывает командные/индивидуальные показатели, позволяет сопоставить треки с UUID игроков и отдельно опубликовать подтверждённую версию.

## Путь оператора

1. В кабинете открыть матч. Во вкладке «Информация» выбрать зал и калиброванный профиль камеры; во вкладке «Составы» сохранить игроков обеих команд.
2. Открыть «Видео и аналитика» → «Создать задание» → «Скачать job.zip». Составы, номера и геометрия сохраняются в неизменяемом снимке задания.
3. На компьютере с установленным Python-окружением проекта и локальными весами `models/yolo11m.pt` выполнить:

```sh
.venv/bin/python -m aifootball.cli process-job --job job.zip --video match.mp4 --output result.zip
```

В новой копии проекта окружение устанавливается через `uv sync`; используйте зависимости из `uv.lock`. Для рабочего сайта нужны также зависимости extra `web`. Разрешение видео должно совпадать с профилем камеры. После детекции программа выполняет трекинг, проекцию в метры, метрики, проверки и упаковку реальных миниатюр.

Если файл содержит только фрагмент матча, добавьте `--partial-recording`. Для известных интервалов в исходной записи доступен `--halves 0:40-21:50,27:10-46:00`. Отсчёт времени не переносится к нулю каждого интервала. Рабочие артефакты остаются рядом с ZIP в каталоге `processor-<UUID>`; `--artifacts <каталог>` допускает повторную упаковку только при совпадении происхождения задания/камеры/видео.

4. Вернуться в тот же матч → выбрать «Пакет результата ZIP» → «Загрузить результат». PDF/HTML можно приложить к ручному протоколу, но индивидуальная статистика формируется только из контракта ZIP.
5. Просмотреть команды A/B, показатели периодов и фрагментов, качество, миниатюры и интервалы. Назначить фрагменты людям из состава либо исключить с причиной. Неизвестные фрагменты остаются без личности.
6. Сохранить сопоставление → «Подтвердить аналитику». Одному человеку можно назначить несколько непересекающихся фрагментов. Подтверждение создаёт метрики и выбирает версию для истории игроков.
7. «Опубликовать аналитику» — отдельная команда. Зрители видят выбранные показатели на странице матча; приватные кадры и административные назначения туда не попадают. Новая внутренняя версия не заменяет публичную автоматически.
8. Открыть игрока из справочника или таблицы отчёта: история считает один активный результат на каждый матч. Для исправления личности в подтверждённой версии используется «Новая проверка игроков», исходная версия сохраняется.

## Право Админ+

Существующим администраторам право не выдано автоматически. Владелец установки выдаёт его явно по логину на машине сервера:

```sh
.venv/bin/python -m aifootball.service.auth.cli grant-analytics --login admin
```

Для отзыва: заменить `grant-analytics` на `revoke-analytics`. Перезагрузка страницы обновляет видимость кнопок; сервер проверяет актуальное право при каждой операции, в том числе в ранее открытой сессии. Обычный администратор может читать внутренний отчёт, но не импортировать, подтверждать или публиковать.

## Данные и повторы

`job.zip` содержит `job.json`, `venue.yaml`, `homography.json`, `pitch_polygon.json`, необязательный `calib.json`, источник CV. `result.zip` содержит `manifest.json`, `report.json`, `track-index.json`, `checks.json`, `thumbs/*.jpg`.

Hash контекста учитывает снимок людей и метрическую геометрию; изменение даты или судей не требует нового задания. Изменение камеры/состава отклоняет несовместимый пакет. Проверяются UUID, размеры, единицы, интервалы, числовые диапазоны, структуры карт, JPEG, список файлов и SHA256. Лимиты по умолчанию: 100 MiB ZIP, 300 MiB распакованных данных, 2048 файлов, 64 MiB JSON, 2 MiB миниатюра; весь HTTP-запрос ограничен до спулинга файлов.

После потери ответа браузер хранит команду с прежним UUID запроса. Для повторной загрузки после перезагрузки страницы нужно выбрать тот же ZIP; SHA256 проверяет совпадение. Конфликт не стирает назначения. Команду можно скачать и снять блокировку, сверить серверную версию и повторить сохранение как новое действие.

Суммируются метры и время основного периода. Темп вычисляется из сумм, скорость — максимум. Таймы не прибавляются повторно к общему периоду. Пропуски не заполняются мостами между треками. Если назначенному фрагменту не хватает метрик, неизвестные показатели сохраняются как `null` с причиной. «Время в анализируемом видео» не считается игровым временем.

- Сквозная проверка: задание → потеря успешного ответа импорта → повтор с тем же ключом → два фрагмента одному UUID → подтверждение → история → отдельная публикация. Второй прогон не удваивает матч; несовместимый пакет сохраняет прежнюю публикацию; обычному админу команды недоступны.
- Независимое ревью: исправлены причины отсутствующей скорости, неизвестные командные показатели, проверка обязательных подписей, предварительный отчёт команд/фрагментов и исключение лишних приватных полей геометрии из публичного DTO. Дополнительно исправлены высота SVG-карт и покрытие при переменном шаге кадров; для ошибок наблюдались RED → GREEN.

## Решения при реализации

1. Сохранён существующий checkout `codex/tournament-service` с прежними незакоммиченными функциями. Цена: изменения разделяют checkout; проверены общие регрессии. До оформления GitHub-репозитория коммит/merge/push не выполнялись; это историческое решение этапа внедрения. Текущая поставка зафиксирована при подготовке репозитория, см. CHANGELOG проекта.
2. Тепловые карты используют общие координаты площадки, без разворота по атаке. Это позволяет объединять карты фрагментов/таймов; цена — для вида «направление атаки» нужен отдельный режим.
3. Отдельная `analysis_revision` матча защищает выбор активной/публичной версии. Цена — дополнительный конфликт при одновременном выборе версий.
4. `--partial-recording` задаётся оператором: по покрытию кадров нельзя определить, содержит ли файл весь матч. Цена — оператор отвечает за отметку полноты исходника.
5. Приёмка использует имеющийся реальный фрагмент и разрешённые пользователем демо-UUID. Цена — реальные личности и точность полного матча ещё не подтверждены.

Отложена небольшая UX-правка: строка задания пока сохраняет надпись «Ожидает внешней обработки» после импорта; актуальный статус результата показан в списке версий и самом отчёте.
