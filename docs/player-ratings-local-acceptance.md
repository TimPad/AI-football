# Локальная приёмка рейтингов игроков

14 октября 2026. Реализован локальный пилотный модуль; проверены программный путь,
арифметика, версии и публикация. Спортивная точность и полезность оценок для тренера
**не подтверждены**. Использованы только синтетические обозначения/UUID.

## Что работает

Админ+ подтверждает протокол, фиксирует присутствие/повторные выходы и роли,
размечает действия и полноту категорий. Полный ручной источник может использоваться
без CV и при наличии дополнительного неполного видео. Видимость трека не подменяет
присутствие. Игровая и видео-шкала не переводятся одна в другую автоматически.

Журнал хранит канонические действия и явные связи: официальный гол + голевой удар
с видео считаются один раз. Не связанный с официальным голом удар с исходом «гол»
отклоняется. Автоголы и серия пенальти не увеличивают личные NPG; неизвестные авторы
не превращаются в подтверждённые нули других игроков затронутой команды.

Версии участия/действий неизменяемы. Расчёт выбирает одну подтверждённую версию
каждого источника на матч, хранит fingerprints, policy и reference. Новый CV run
или редакция не удваивают выступление. Изменение каталожного амплуа не переписывает
роль в старом матче. Фильтр команды использует команду конкретного матча; стадия —
явно введённое `stage_label`, а не название варианта регламента.

В матче доступны участие, журнал, компоненты, объяснение и проверенные примеры.
В турнире — общий/позиционные списки и исходные метрики, фильтры и фиксированный
snapshot при пагинации. В карточке игрока — история выбранного турнира и динамика
внутри совместимого издания. Пропуск оценки не рисуется нулевой точкой.

## Формула и допуск

- `rate10 = 600 × count / eligible_play_s`. `per10-possession` использует отдельно
  проверенное владение/время без владения; это другое издание. Турнирные rates и
  проценты — отношение сумм числителей и знаменателей.
- Для каждой роли reference требует минимум 5 UUID и 20 допустимых player-match
  одной базы времени, уровня, турнира и профиля. Дата отсечения зафиксирована;
  используется дата матча из сохранённого расписания. Это не модель силы лиги.
- Empirical midrank: `100 × (число меньших + 0.5 × число равных) / N`.
  Нежелательные показатели инвертируются. Доли успехов сглаживаются к отношению
  сумм reference с prior strength 10 **попыток**. К count/time не прибавляются
  вымышленные десять секунд. Полный ноль возможностей даёт нейтральные 50;
  неизвестный знаменатель остаётся неизвестным.
- Компоненты и веса: [policy role-profile-v1](../configs/ratings/role-profile-v1.json).
  Неизвестный обязательный компонент блокирует S, веса не перенормируются.
  Физическая нагрузка вынесена отдельно, вес 0. GK save% — proxy без сложности удара.
- Матч: S 0–100; отображение `round(1 + 9 × S / 100, 1)`. Несколько ролей
  взвешиваются допустимыми минутами, неизвестная роль не распределяется между ними.
  Итог матча требует ≥3 минут и ≥80% покрытия. Роль и итог матча показаны отдельно.
- Турнир: `u=min(допустимые минуты/10,1)` один раз на матч;
  `T=(ΣuS + 3×50)/(Σu+3)`. Один матч S=80 → 57.5; пять → 68.75.
  Без допустимых матчей T=null. Основной список: ≥3 оценённых матча, ≥20 минут,
  coverage оценённого/известного сыгранного времени ≥80%. Неизвестное общее время
  означает неизвестный допуск. Равные неокруглённые S/T сохраняют равные места.

Это экспериментальные пороги и эвристические веса; они не выдаются за формулу
Opta/Sofascore, оценку таланта или подтверждённую модель вероятности.

## Независимая численная проверка

```sh
.venv/bin/python scripts/verify_tournament_ratings.py
.venv/bin/python -m pytest tests/test_ratings_acceptance.py --tb=line -q
```

Verifier строит 100 синтетических выступлений: 5 игроков × 4 матча для каждой
из 5 ролей. Известные counts/600 секунд, midranks 10/30/50/70/90 и буквальные
позиционные веса дают независимый эталон для всех 100 матчевых баллов. Expected
values не вызывают `scoring.py`. Проверяются суммы, ratio-of-sums, appearances,
shrinkage, одинаковая reference при перестановке входа, неизвестное участие,
неполная категория, плохой видеоисточник, минутное выступление и нулевой вес бега.

Детерминированный fingerprint этого набора:
`a57039491646d5a5e0e40ea8c5ef8ddffc3a920c919f1d6184029f8c580fafb5`.

Проверка чувствительности двух сопоставимых профилей фиксо:

| Finishing / Defence | S(A) | S(B) | Порядок |
|---|---:|---:|---|
| .05 / .45 | 47.3 | 48.8 | B выше A |
| .10 / .40 | 47.6 | 47.6 | Равенство |
| .15 / .35 | 47.9 | 46.4 | A выше B |

Сдвиг веса на .05 способен изменить места. Это подтверждает необходимость
калибровки и сохранения версий, а не объективность выбранных коэффициентов.

## Проверки сервиса и интерфейса

Реальные API-тесты проверяют идемпотентность, конфликт payload/revision, rollback,
новую CV-версию, сохранение исторического амплуа, независимые публичные источники,
отказ публикации private/stale среза, одинаковые строки при одинаковом fingerprint,
пагинацию, команды/стадии и отсутствие закрытых заметок/кадров в публичных DTO.

Playwright создаёт отдельный синтетический турнир в `aifootball_e2e`: 6 игроков ×
4 матча. Проверяет редактирование действий, committed-but-lost response и тот же
request_id после перезагрузки, новый private snapshot, позиционную таблицу,
отдельный public snapshot, старое издание и неизменность официального протокола.
Копия БД и файлов восстановлена и точно сверена, включая ratings/participation/actions.
Рабочая база организатора в проверках не очищалась и не мигрировалась.

Перед публикацией:

```sh
.venv/bin/python -m pytest --tb=line -q
npm --prefix web run test
npm --prefix web run build
npm --prefix web run test:e2e
.venv/bin/python scripts/verify_service_backup.py --source e2e
git diff --check
```

Browser plugin отсутствует; использован штатный Playwright fallback. Десктоп и
390 px проверены по скриншотам; таблица прокручивается внутри блока, страница не
расширяется. Включены тесты локального черновика, 409, потери ответа, повреждённого
ввода, unknown/zero и отображения HTML как текста.

## Публикация и ограничения

Публикация источников и рейтинга — отдельные операции. Сначала опубликуйте протокол
и связанный CV run, если он используется. В матче разрешите выбранные версии участия/
действий и текущую policy. Рассчитайте public-scope срез; его отдельная публикация
подтверждает соответствующее reference из опубликованных источников. Private-scope
срез нельзя просто сделать видимым гостю. Изменившиеся входы требуют пересчёта;
старое публичное издание сохраняется до явной публикации нового.

Нет полной независимой разметки реального матча, coach review и подходящей реальной
reference по каждой роли. Поэтому здесь нет sporting acceptance, обещания полноты
автоматической разметки передач и подтверждения реальных личностей. Разбиение
будущего train/control выполняется по матчам, не соседним кадрам.

Шаблон объяснения выбирает до 3 полезных действий и 3 ошибок из подтверждённого
журнала; это не исчерпывающий перечень и не причинная модель. Публичное объяснение
не содержит ссылок на закрытые JPEG. Синтетическая проверка соответствия UUID/роли/
действия не заменяет оценку полезности этих примеров тренером.

xG/xA, PSxG/GSAA, xT/VAEP и поправка на силу соперника не обучены и не реализованы.
Командные фазы по всему турниру — отдельное расширение; текущие CV-командные отчёты
остаются по матчу/периоду. Connected Processor, S3, очередь/lease, Colab и облачная
GPU-ВМ ещё не реализованы/не развёрнуты. Live Qwen и CUDA — отдельная приёмка,
см. [приёмку Qwen](2026-10-14-qwen-local-acceptance.md).
