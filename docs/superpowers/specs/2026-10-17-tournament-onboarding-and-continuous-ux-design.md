# Сквозной UX/UI турнира, составов и публикации

17 октября 2026. **Предложение для обсуждения; реализация не начата.**

Запрос: улучшить клиентскую часть, кабинет администратора и Админ+, сделать управление естественным и связанным; при создании турнира разрешить сразу добавить команды и игроков, загружать состав целиком. Пользователь уточнил: основной источник состава — **таблица Excel**. Дополнения: подсказки адреса зала из карт, регистрация капитана, самостоятельное создание команды/игроков и подтверждение капитаном соответствия кадров игрокам своей команды. **18 октября:** стартовая страница зрителя — календарь матчей с группировкой по турнирам по аналогии с Sofascore, дополненный ближайшими играми.

## 1. Цель и принятые для плана допущения

Организатор проходит путь «турнир → команды → заявки → матчи → протокол → публикация» в контексте турнира, без обязательных походов в справочники. Зритель проходит обратный путь: «турнир → команда → матч → игрок» с сохранением выбранного дня и фильтров.

«Нативность» в этом предложении означает привычное поведение веб-приложения: короткие формы, создание связанной сущности на месте, понятное сохранение, работа клавиатурой и предсказуемый возврат. Это интерпретация автора плана. Сохраняем React/TypeScript/FastAPI и визуальные токены от 15 октября; отдельное мобильное приложение в объём не входит.

Клиентская часть включает существующий гостевой сайт и добавленный пользователем кабинет капитана. [Регистрация, права, состав и самостоятельное подтверждение кадров](2026-10-17-captain-self-service-design.md) выделены в отдельную спецификацию, связанную с этим проектом. Личный вход каждого игрока пока не требуется.

## 2. Что существует и где рвётся сценарий

Проверены код, README, предыдущие UX-документы; гостевая главная и страница турнира дополнительно просмотрены в браузере на локальном сервисе. Кабинеты оценены по реализации и тестовым сценариям; новую визуальную приёмку кабинетов в этой работе не проводили.

## 3. Общие правила UX/UI

1. Основное действие соответствует текущей задаче: «Добавить команды», «Проверить строки», «Применить импорт», «Создать матч». Недоступное действие сопровождается причиной и переходом к исправлению.
2. Хлебные крошки сохраняют турнир; возврат из команды/матча восстанавливает день, фильтры и вид расписания. Параметры адреса допускают прямую ссылку.
3. Короткое создание одной сущности — боковая панель; мастер турнира и импорт — полноценная страница. У сложной формы есть постоянная область действий и видимый статус сохранения.
4. У состава на первом экране видны ФИО, номер, амплуа и состояние строки. Фото, дата рождения, рост и вес открываются в деталях; широкая таблица со всеми полями не является обязательным способом ввода.
5. Поиск с выбором заменяет длинные списки игроков. Можно выбрать несколько существующих команд, проверить их заявки и добавить одним действием.
6. Локальный черновик подписан «Черновик на этом устройстве»; серверное сохранение — «Сохранено». Потерянный ответ не равен ошибке сохранения: доступен повтор той же команды.
7. После закрытия панели сохраняется фокус на вызвавшем элементе. Диалоги удерживают фокус; Escape учитывает несохранённый ввод. Ошибки привязаны к полю/строке, первая ошибка доступна с клавиатуры.
8. На узком экране — список, карточки игроков и панель во всю ширину. Работающие токены, палитра и компоненты остаются основой.

## 4. Создание турнира: два равноценных пути

На первом шаге: название, сезон, даты, часовой пояс. После заполнения доступны:

- **«Создать турнир»** — сохранить черновик, открыть обзор турнира с действиями настройки. Команды и регламент можно добавить позже.
- **«Создать и добавить команды»** — сохранить тот же черновик и продолжить мастер: регламент → команды и игроки → проверка.

Регламент выбирается из существующего стартового шаблона; основные параметры видны сразу, подробные — по раскрытию. Не добавлять вымышленные форматы групп/плей-офф до появления соответствующей модели.

На шаге команд доступны три действия: выбрать существующие, создать команду на месте, загрузить команды и заявки из Excel. У каждой команды видны число игроков и проблемы. Уже готовый постоянный состав предлагается к включению с предпросмотром и учётом лимита регламента.

Все шаги можно сохранить и продолжить позже. Выполненные серверные операции не откатываются при переходе «Назад». Выход из мастера оставляет явно обозначенный черновик; повторное нажатие после сетевой ошибки не создаёт второй турнир.

Финальный экран показывает созданные команды, заявки, регламент и действия «К матчам» / «Продолжить настройку». Публикация турнира — отдельная явная команда. Отсутствие матчей разрешено: на публичной странице будет честное пустое состояние. Публикация страницы турнира не публикует результаты, CV и рейтинги.

Обзор турнира показывает готовность: сведения, регламент, команды/заявки, расписание, видимость сайта. Следующее действие выбирается из незавершённых задач; это вычисляемая сводка, а не отдельный источник состояния.

## 5. Excel: один импорт для трёх точек входа

Один компонент импорта используется в мастере, в «Командах турнира» и в карточке команды. Поддержка `.xlsx` входит в первую поставку. CSV, вставка текста, старый `.xls`, PDF, фото и OCR отложены.

### Вход и шаблон

- В турнире можно загрузить один лист с несколькими командами; столбец «Команда» группирует строки. Для одной выбранной команды этот столбец не нужен.
- Если в книге несколько непустых листов, пользователь выбирает один; автоматического импорта всех листов нет. Несколько листов импортируются отдельными операциями.
- Столбцы шаблона: `Команда`, `ФИО`, `Номер`, `Амплуа`, `Дата рождения`, `Рост, см`, `Вес, кг`. Обязательно только ФИО и команда при импорте нескольких команд. Скачать шаблон `.xlsx` можно рядом с загрузкой.
- Принимаются и отдельные столбцы фамилии/имени/отчества: пользователь сопоставляет их, приложение собирает отображаемое ФИО. Синонимы заголовков предлагаются автоматически, окончательное сопоставление видно человеку.
- Даты: Excel date, `ДД.ММ.ГГГГ` или `ГГГГ-ММ-ДД`; неоднозначные строковые даты требуют исправления. Номер хранится строкой; ведущие нули текстового значения сохраняются.
- Предложенные технические пределы первой поставки: файл 5 МиБ, распакованная книга 25 МиБ, книга суммарно до 1 000 непустых строк на всех листах, выбранный лист до 64 команд. Это решения автора плана, а не подтверждённые характеристики существующего импорта.

### Путь пользователя

`Файл → лист и столбцы → проверка строк и совпадений → итог изменений → применить`.

Предпросмотр содержит исходный номер строки Excel, команду, игрока, действие и объяснение. Фильтры: «Все / Ошибки / Возможные совпадения / Пропущенные». Пример итога: «3 новые команды, 24 новых игрока, 12 существующих игроков, 2 строки требуют решения».

Ошибки исправляются в таблице предпросмотра, без обязательного редактирования и повторной загрузки Excel. Изменение столбцов или решения о совпадении пересчитывает итог. Строку можно явно исключить; пропущенные строки остаются видны в итоговом отчёте.

Импорт применяется только после устранения блокирующих ошибок среди выбранных строк. Все выбранные строки сохраняются одной транзакцией; при ошибке не возникает половины команды. После применения показываются итог, ссылки на команды/заявки и отчёт ошибок для скачивания.

### Совпадения и история

- Стабильный UUID определяет личность игрока. ФИО, дата рождения, номер и команда — признаки поиска, но не разрешение на автоматическое объединение.
- При возможном совпадении человек выбирает существующего игрока либо явно создаёт нового. Однофамильцы и одноимённые команды не сливаются автоматически. Архивная сущность требует отдельного восстановления вне импорта либо выбора другого решения.
- Пустая ячейка не стирает известные сведения. В первой поставке импорт заполняет профиль нового игрока, а для существующего использует UUID и номер заявки; изменение его общей карточки выполняется отдельным редактором.
- По умолчанию импорт **добавляет** игроков, сохраняя тех, кого нет в файле. Замена всего состава и массовое удаление не входят в первую поставку.
- В карточке команды импорт изменяет постоянный состав (`TeamMember`). В турнире — заявку (`EntryPlayer`), создавая при необходимости команды и карточки игроков; постоянный состав существующих команд не меняется. Эта область действия явно написана перед применением. Для новой команды можно позднее перенести заявку в постоянный состав отдельной командой с предпросмотром; это следующий этап.
- Изменение постоянного состава не переписывает заявки других турниров; изменение заявки не меняет уже зафиксированные составы/подтверждённые версии матчей. В матч по-прежнему отдельно выбирают участников из заявки.
- Повтор той же подтверждённой команды возвращает тот же результат. Повторная загрузка файла создаёт новый предпросмотр со сравнением с текущими данными, а не автоматически дублирует людей.

### Блокирующие условия

Пустое ФИО, нерешённое совпадение, повтор UUID/непустого номера внутри одной заявки, превышение регламента, невозможная дата/параметр, архивный турнир, устаревшая ревизия. Формулы в используемых ячейках, защищённая/повреждённая книга и неподдерживаемый формат объясняются на этапе чтения; макросы и внешние источники не исполняются. Номера в разных командах разрешены.

## 6. Администратор: управление от турнира

- В «Командах» турнира — поиск, множественное добавление, создание на месте, импорт Excel, число заявленных игроков и адресное исправление ошибок.
- Карточка заявки показывает прежде всего игроков этой команды; существующих людей добавляют через поиск, новых — прямо в строке или панели. Видно различие «Постоянный состав» / «Заявка этого турнира» / «Состав матча».
- В форме матча можно создать недостающую команду или зал и вернуться с сохранённой датой и соперником. Камерная калибровка не становится условием создания обычного матча.
- Обзор турнира и фильтр «Требуют внимания» ведут к конкретной задаче: нет заявки, не выбран зал, протокол не подтверждён, подтверждённая версия ещё не опубликована.
- Пакетно добавлять команды/заявки можно; массовую публикацию и редактирование подтверждённых матчей в этот этап не включаем.
- В строке матча различимы «Нет результата», «Черновик протокола», «Подтверждён», «На сайте», «Есть новая версия». Протокол можно подготовить и опубликовать без видеоаналитики.

## 7. Админ+: очередь работы и связь с публикацией

Админ+ получает все возможности администратора. Дополнительно в обзоре турнира есть «Работа с аналитикой»: список матчей с фильтрами «Ожидает проверки / Назначения не завершены / Данные не подтверждены / Готово к публикации / Рейтинг требует пересчёта».

Это обзор существующих заданий, запусков и версий, а не новый облачный обработчик. Источники сводки — существующие API аналитики и рейтингов; при реализации добавить пакетную сводку, избегая запроса на каждый матч.

Из строки открывается нужный матч, версия и задача. При возврате сохраняются фильтр, выбранный матч и позиция списка. Внутри матча остаются четыре текущих раздела. Инструкции внешнего CLI и технические параметры раскрываются по запросу, UUID не нужно вводить вручную.

Перед подтверждением видно число неназначенных фрагментов, несохранённые изменения и блокирующие причины. Перед публикацией — сравнение текущих публичных данных с выбранными версиями. Статусы протокола, CV, разрешений данных и рейтинга независимы; старая публичная версия остаётся до явной публикации новой.

Обычный администратор видит относящийся к матчу безопасный статус аналитики и пояснение, кому доступно действие; закрытые материалы и команды Админ+ не запрашиваются. «Админ+» по-прежнему означает право аналитики, а не новое управление пользователями или организациями.

## 8. Гостевой сайт: законченные связи

1. Главная `/` и `/watch` — матчи выбранного дня, сгруппированные по UUID турнира. Сверху календарь/лента дат и фильтры «Все / Идут / Предстоящие / Завершённые», рядом выбор турнира и поиск. На desktop — отдельный компактный блок до 3 ближайших матчей, на телефоне он свёрнут. Каталог турниров доступен дополнительно. [Отдельная спецификация новой главной](2026-10-18-public-match-center-design.md) определяет зоны времени, публикацию, пагинацию и пустые дни.
2. В турнире — «Матчи / Команды / Рейтинги». «Команды» ведут в публичную карточку команды в контексте этого турнира: опубликованные участники, предстоящие матчи и результаты.
3. Имена команд в расписании и шапке матча становятся ссылками. Игрок из опубликованного состава открывается даже без рассчитанного рейтинга; история оценок — раздел карточки, а не единственное её содержание.
4. Публичный состав команды строится только из опубликованных протоколов этого турнира. Импорт заявки не делает её публичной. До первого опубликованного состава показываются команда и расписание с пояснением «Состав ещё не опубликован».
5. Публичные карточки не раскрывают дату рождения, рост/вес, фото, закрытую заявку, кадры проверки. ФИО и номер берутся из опубликованного снимка; UUID нужен для навигации, не для отображения.
6. Новые разделы используют отдельные публичные API. Таблица результатов турнира по местам требует отдельного расчёта и правил равенства очков; в эту поставку не входит и с рейтингом игроков не смешивается.
7. В расписании можно фильтровать выбранную команду; возврат из матча сохраняет фильтры. На телефоне первичен список, широкая сетка доступна дополнительно.
8. Неизвестный счёт остаётся «— : —», недоступная метрика — с причиной, историческое издание рейтинга не заменяется текущим. ВК-плеер загружается после нажатия, как сейчас.

| Подготовить заявку турнира | Нет | Только своей команды | Да | Да |
| Утвердить заявку, вести/публиковать ручной протокол | Нет | Нет | Да | Да |
| Просмотр кадров и самостоятельное подтверждение UUID | Нет | Выданная задача своей команды | Без новых прав на назначения | Да |
| Техническое подтверждение общего CV, участие/действия и публикация рейтинга | Нет | Нет | Нет | Да |

Новые турниры имеют `visibility=draft`; существующие при миграции получают `public`, сохраняя текущие ссылки. `archived` остаётся независимым флагом. Все публичные маршруты, включая протокол по public ID, CV, рейтинги, статистику действий и изображения, проверяют видимость родительского турнира. Для закрытого турнира ответ — 404. Предпросмотр доступен в авторизованном кабинете; отдельной публичной секретной ссылки не добавляем.

## 10. Технические границы

- Сохраняются каталог игроков/команд, `TeamMember`, `Entry`, `EntryPlayer`, версии регламентов и составы матчей. Мастер организует эти сущности, а не дублирует их новой моделью «турнир целиком».
- Новые команды создания турнира/связанных команд и применения импорта имеют `request_id`, проверку содержимого повтора и ревизий затронутых записей. Транзакции применяют ограничения существующих операций.
- Серверный предпросмотр импорта хранит значения/типы ячеек всех листов в ограниченном нормализованном виде для повторного выбора листа/столбцов, затем строки, решения, область действия и ревизию. Исходный Excel постоянно не сохраняется; предпросмотр доступен своему автору и удаляется по явной отмене либо через 7 дней без изменений. Результат применённой команды остаётся для безопасного повтора.
- Миграции только новые. Публичная схема и frontend-типы обновляются вместе. Библиотека чтения `.xlsx` выбирается при реализации после проверки официальной документации, фиксируется в `uv.lock`; новую UI-библиотеку ради этого этапа не вводим.
- Ручной протокол и CV остаются разными источниками. Connected Processor, OCR, маски, S3, Colab и платные VLM-вызовы не входят в этот UX-проект.

## 11. Очерёдность и приёмка

| Поставка | Что получает пользователь | Приоритет |
|---|---|---|
| A | Черновик турнира, два пути создания, команды и заявки на месте, Excel с предпросмотром | P0 |
| A1 | Подсказки адреса зала и выбор точки из карт, включая быстрое создание | P0, отдельная независимая задача |
| B | Общий обзор готовности, сохранение контекста, удобные заявки/формы/сохранение и адаптация | P1 |
| C | Очередь Админ+ и сравнение публикаций | P1 |
| D0 | Главная: календарь дат, группы матчей по турнирам, поиск/статусы, ближайшие игры и топ-5 опубликованного рейтинга выбранного турнира | P1, первая клиентская поставка |
| D1 | Публичные команды/игроки, связи и командный фильтр | P1 |
| E1 | Регистрация капитана, свои команды/игроки и Excel | P1, требуется пользователем |
| E2 | Подача и утверждение турнирной заявки капитана | P1 |
| F | Самостоятельное подтверждение своей стороны по кадрам после импорта | P1, требуется пользователем |
| Позже | Копирование сезона, замена состава, перенос заявки в постоянный состав, CSV/текст, вход каждого игрока | P2, отдельное решение |

Поставка A — первый законченный результат. A1 можно делать независимо; E1 опирается на Excel из A, F — на E1 и существующий импорт CV. D0 можно выпускать сразу после visibility A, независимо от капитанского кабинета и профилей D1; она становится первой клиентской поставкой. B/C/D1 выпускаются отдельно. Цветовые изменения без улучшения сценариев не считаются выполнением запроса.

Подробности дополнений: [адрес зала](2026-10-17-hall-address-suggest-design.md) и [кабинет капитана](2026-10-17-captain-self-service-design.md). **Зафиксировано пользователем: капитан самостоятельно подтверждает свою команду, без принятия каждого назначения Админ+.** Общая техническая версия аналитики и публикация — отдельные стадии.

Критерии:

- Из создания турнира можно пройти до двух команд с заявками и первого матча, не открывая справочники в другом контексте.
- Книга с 3 командами и 45 синтетическими игроками импортируется одной операцией с понятным итогом; номер 7 в разных командах допустим.
- Одна ошибочная строка не требует повторного ввода остальных; новые люди не смешиваются с однофамильцами.
- Повтор после потерянного ответа не создаёт вторые турнир/команды/игроков. Конфликт ревизий сохраняет ввод и требует обновить предпросмотр.
- Прерванная настройка продолжается с сохранённого места. Неопубликованный турнир недоступен гостю даже по прямым ссылкам на дочерние данные.
- Обычный администратор завершает ручной матч и публикует протокол без прав Админ+; Админ+ попадает из очереди в нужную версию и возвращается с теми же фильтрами.
- Зритель проходит «турнир → команда → матч → игрок → назад» без потери контекста и без раскрытия импортированных закрытых сведений.
- Главная открывает сегодняшний календарь с группами турниров; пустой выбранный день не заменяется ближайшим автоматически. Возврат из матча восстанавливает дату/фильтры; счёт и счётчики не раскрывают черновики.
- Адрес зала выбирается из подсказок; ручная правка убирает устаревшую точку, недоступность карт не блокирует ввод.
- Капитан регистрируется, создаёт свою команду/игроков, использует Excel и самостоятельно подтверждает UUID только своей стороны. Чужие назначения сохраняются, общий run не замораживает открытые задачи второго капитана.
- Ручная приёмка: 1440, 1024 и 390 px, клавиатура, длинные имена, пустые данные, загрузка, 422, 409, потерянный ответ и истёкшая сессия. Целевой ориентир, ещё не измеренный: загрузить корректный состав из 15 игроков за 2 минуты без ручного перепечатывания.

Проверки реализации выполняются на синтетических данных в `aifootball_test`, `aifootball_migration_test`, `aifootball_e2e`. Рабочие данные организатора и общий `web/dist` для приёмки не перезаписываются.
