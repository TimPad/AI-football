# Подсказки игрока для оставшихся фрагментов (26 ноября 2026)

> **Статус (26.11.2026):** спецификация этапа 1; этап 2 — набросок, отдельная спецификация после этапа 1.

## Зачем

На вкладке «Проверка» после основной разметки остаётся хвост коротких фрагментов. Матч ВШЭ Ю — JWH 22.11.2026
(поворотная камера трансляции): у ВШЭ Ю 513 фрагментов назначены 9 игрокам, неназначенными остаются 286 фрагментов
игроков и вратарей — 17% игрового времени команды, половина короче 4 с.

Существующие режимы назначают по одному фрагменту («По фрагментам») или по одному игроку за раз («Подбор»: похожие
фрагменты выбранного игрока по цвету формы). Чтобы закрыть хвост, приходится перебирать игроков и не видно, какому
игроку фрагмент подходит лучше всего. Нужен обратный взгляд: каждому оставшемуся фрагменту — лучший игрок, все
игроки команды сразу.

Подсказки только упорядочивают и отмечают предложения; назначает человек. Сборка людей по внешности без человека
проверку не прошла (точность склеек 0,50, [замер](../../2026-11-23-people-clustering.md)).

## Замер

Данные — прогон `3a18736a` матча ВШЭ Ю — JWH, 513 назначенных фрагментов ВШЭ Ю. Для каждого назначенного
фрагмента его игрок прятался и угадывался по остальным назначениям (по одному вне выборки).

| Признак | Подсказка есть | Верно | Верно на фрагментах < 4 с |
|---|---|---|---|
| Цвет формы — косинус признака внешности к среднему игрока, как в «Подборе» | 92% | 83% | 67% |
| Продолжение — фрагмент начинается ≤ 2 с после конца другого, ≤ 1,5 м + 7 м/с × разрыв от его конца | 33% | 94% | 90% |
| Вместе: продолжение, иначе цвет | 96% | 88% | 79% |

Игроки, видные одновременно с фрагментом (больше 1 с перекрытия, правило сервера), исключаются заранее.

Точность подсказки по цвету растёт с отрывом лучшего игрока от второго:

| Отрыв не меньше | Доля подсказок | Верно | Верно на фрагментах < 4 с |
|---|---|---|---|
| 0 | 100% | 83% | 67% |
| 0,01 | 82% | 91% | 75% |
| 0,03 | 42% | 93% | 82% |
| 0,05 | 20% | 97% | 92% |

Из 286 оставшихся фрагментов признак цвета есть у 148: подсказку по цвету получат они. Продолжение добавит ещё ~22
(170 всего), остальные ~116 без признаков остаются ручными. На хвосте точность будет ниже замера: неназначенными
остались трудные фрагменты.

Скрипт замера — вне репозитория (scratchpad сессии, `identity/measure.py`, `identity/margin.py`); позиции концов
фрагментов для продолжения брались из `state.parquet` обработки, в пакете результата их нет.

## Этап 1: режим «Подсказки» по цвету

Меняется только кабинет. Обработчик, пакет результата, сервис, схема базы и API не меняются.

### Расчёт подсказок

Чистая функция в `web/src/features/analysis/suggestions.ts`, без обращений к серверу:

- **Кандидаты** — как в «Подборе»: группы склейки прогона (`baseGroups`, `candidatesOf`) выбранной команды с ролью
  игрока или вратаря, по которым в черновике нет решения (`decisionOf(...).kind === 'none'`).
- **Игроки** — состав стороны команды (по `side_map` черновика), у которых в черновике есть хотя бы один фрагмент.
- **Допустимые игроки кандидата** — не видны одновременно с ним: ни один фрагмент игрока не перекрывает кандидата
  больше чем на `HANDOFF_S` = 1 с (`clash` из `similar.ts`, порог из `candidates.ts`).
- **Оценка** — косинус среднего признака кандидата к среднему признаку игрока с весом по времени на площадке
  (`meanLook`, `cosine`), как в «Подборе». Кандидат без признака подсказки не получает.
- **Отклонения** — пара «игрок, кандидат», отклонённая кнопкой «Не он», из допустимых исключается; тогда подсказкой
  становится следующий по оценке игрок. Отклонения живут, пока открыт режим, и не сохраняются (как в «Подборе»).
- **Результат**: для каждого кандидата — лучший игрок, его оценка и отрыв от второго допустимого игрока (при одном
  допустимом — отрыв от нуля). Кандидаты без признака и без допустимых игроков возвращаются отдельно, с причиной.
- **Уверенность**: подсказка «уверенно», если отрыв ≥ `CONFIDENT_MARGIN` = 0,03, иначе «сомнительно».

Пересчёт — при каждом изменении назначений черновика: меняются средние признаки игроков и допустимость по времени.
На прогоне в 1641 фрагмент и 12 игроков расчёт — порядка 300 × 12 косинусов по 156 числам, без кэша на сервере.

### Экран

Компонент `web/src/features/analysis/SuggestionPicker.tsx`, режим **«Подсказки · N»** в переключателе вкладки
«Проверка» рядом с «Подбор / По игрокам / По фрагментам». N — число кандидатов с подсказкой у обеих команд.
Режим показывается, когда у прогона есть признаки внешности (как «Подбор»).

- Переключатель команды — как в «Подборе».
- Подсказки сгруппированы по игроку: заголовок «№ · Имя — k подсказок», группы по убыванию числа подсказок.
- Внутри группы карточки по убыванию оценки: миниатюра самого длинного фрагмента кандидата (или «Кадр недоступен»),
  отрезок времени, длительность, метка «уверенно»/«сомнительно».
- Отметка карточки: флажок «Назначить». Уверенные отмечены сразу, сомнительные — нет. Два кандидата одного игрока
  могут быть видны одновременно друг с другом: тогда сразу отмечается только более похожий (обход по убыванию
  оценки), а флажок кандидата, видного одновременно с уже отмеченным, недоступен — как «Он» в «Подборе».
- Кнопка «Не он» на карточке — отклонить этого игрока для кандидата; карточка уходит к следующему игроку или в
  «Без подсказки».
- Кнопка группы «Назначить отмеченных (k)» — назначает отмеченных кандидатов игроку группы в черновике
  (`assignGroup`), группы и средние пересчитываются.
- Внизу — «Без подсказки: N» с причинами («нет признака цвета», «все игроки видны одновременно»): их назначают в
  «По фрагментам».
- Если у команды ни у одного игрока нет фрагментов: «Сначала назначьте каждому игроку хотя бы один фрагмент в
  «Подборе»» и кнопка перехода в «Подбор».
- Режим недоступен для правки там же, где и другие (`disabled`: только просмотр, идёт сохранение, повреждён
  черновик).

### Сохранение

Как в других режимах: назначения меняют черновик сопоставления, на сервер их отправляет «Сохранить сопоставление».
Предупреждение об устаревшем черновике (PR #45) действует и здесь.

### Проверка

- Модульные тесты `suggestions.test.ts`:
  - игрок, видный одновременно, не предлагается;
  - отклонённая пара даёт следующего игрока;
  - отрыв и порог «уверенно»: у одинаковых по цвету игроков отрыв 0 — «сомнительно», «уверенно» ровно при
    отрыве ≥ 0,03;
  - из двух уверенных кандидатов игрока, видных одновременно, сразу отмечен только более похожий;
  - кандидат без признака и кандидат без допустимых игроков попадают в «Без подсказки» с причиной;
  - игроки без фрагментов не предлагаются;
  - пересчёт после назначения меняет среднего игрока.
- Тест компонента: группы по игрокам, уверенные отмечены, снятие отметки, «Не он», «Назначить отмеченных» меняет
  назначения черновика, пустое состояние.
- E2E: продолжение `similar-picker.spec.ts` — после назначения в «Подборе» режим «Подсказки» предлагает
  оставшийся фрагмент тому же игроку и назначает его.
- Общие: Biome, `tsc -b`, `vite build`, vitest, E2E с флагами CI.

## Не входит

- Продолжение трека (этап 2) и любые изменения обработчика и пакета.
- Модель, обучаемая на матче (эмбеддинги миниатюр): точнее, но тяжёлая зависимость в сервисе и отдельный замер.
- Подсказки для судей и фрагментов без команды, массовое исключение.
- Автоматическое назначение без человека, сохранение отклонений между сеансами.

## Этап 2 (набросок)

- Обработчик кладёт в `track-index.json` начало и конец каждого фрагмента: время и позицию на площадке в метрах.
  Версия пакета и проверка импорта — по правилам обмена.
- Подсказка по продолжению идёт раньше цвета: фрагмент, начинающийся ≤ 2 с после конца назначенного фрагмента и
  ≤ 1,5 м + 7 м/с × разрыв от него (и симметрично — перед началом следующего), получает его игрока с меткой
  «продолжение фрагмента» и отметкой сразу.
- JWH перепаковывается из готовых артефактов обработки (`process-job --artifacts`), назначения переносятся в новый
  прогон.
- Отдельная спецификация и замер на том же хвосте.
