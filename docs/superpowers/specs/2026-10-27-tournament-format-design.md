# Формат турнира, жеребьёвка, таблицы и сетка

27 октября 2026. Закрывает п. 4 аудита UX от 26 октября: «нет турнирной таблицы». Также вводит этапы турнира, которые спецификация от 15 октября отложила. **Согласовано с пользователем; реализация не начата.**

## 1. Задача и принятые решения

Организатор задаёт формат турнира из этапов, проводит жеребьёвку, получает пары по турам и раундам и назначает им дату и зал. Зритель, в основном с телефона, видит таблицы групп, сетку плей-офф и пары без даты.

Решения пользователя:

| Вопрос | Решение |
|---|---|
| Форматы первой поставки | круговой в 1 и 2 круга, группы → плей-офф, плей-офф на выбывание, двойное выбывание, швейцарская система; сочетания собираются из этапов |
| Места при равенстве очков | сначала личные встречи (как в АМФР и УЕФА); порядок меняется в настройках этапа |
| Пара плей-офф | по умолчанию один матч; для любого раунда можно включить два матча по сумме |
| Правка жеребьёвки | свободно до первого подтверждённого протокола этапа; затем только замена команды в несыгранных парах |
| Дата и зал | пары создаются без даты; организатор назначает дату и зал позже |
| Посев | организатор выстраивает команды по силе; следующий этап сеется по таблице предыдущего |
| Гранд-финал двойного выбывания | один матч; переигровка включается настройкой и появляется, только если победила команда из нижней сетки |
| Сетка из групп | автосхема (A1–B2, B1–A2, лучшие третьи), видна заранее, правится в предпросмотре |
| Очки за серию пенальти в группе | не нужны: в группе только победа, ничья, поражение |
| Турниры без формата | общая таблица по всем опубликованным матчам; организатор может её скрыть |

Не входит в поставку: матчи за 5–8 места и полная классификация проигравших (кроме матча за 3-е место); ограничения жеребьёвки вроде «команды одного города в разные группы»; «честная игра» (карточки) как критерий; автоматическая раскладка пар по датам.

## 2. Что есть сейчас

- Турнир (`tournaments`), заявки команд (`entries`), версии регламента (`regulations`: очки, `allow_draw`, дополнительное время, серия пенальти).
- Матч (`matches`) обязательно имеет обе заявки, дату, зал и регламент. Стадия хранится только свободным текстом `stage_label`, по нему же работает фильтр «Стадия турнира» в рейтингах.
- Результат зритель видит только из опубликованной версии протокола (`ProtocolVersion.snapshot`: `projection.effective_score`, `protocol.shootout_totals`, `protocol.result_type`). Подтверждённая версия и публикация — разные операции.
- Команды настройки выполняются идемпотентно через `setup_command` (ключ `request_id`, хэш тела, сохранённый ответ).
- Удаления матчей нет; у матча есть статус `cancelled`.

Матч без даты или без соперника противоречит инвариантам матча и всем его потребителям (календарь, центр матчей, рейтинги, очередь обработки). Поэтому вводится отдельная сущность — **пара этапа**. Матч создаётся только при назначении даты и только когда обе команды известны.

## 3. Модель данных

Одна новая миграция `0027_tournament_stages`.

### `stages`
| поле | смысл |
|---|---|
| `tournament_id`, `position` | порядок этапа в турнире (уникален в турнире) |
| `name` | «Групповой этап», «Плей-офф»; задаёт организатор |
| `kind` | `round_robin`, `groups`, `single_elim`, `double_elim`, `swiss` |
| `regulation_id` | регламент матчей этапа (для плей-офф обычно с `allow_draw=false`) |
| `config` JSONB | настройки вида, см. ниже; проверяются Pydantic-схемой |
| `lots` JSONB | введённый жребий: порядок команд по группе или по сравнению лучших одного места |
| `revision` | оптимистическая блокировка |

`config` по видам:
- общие: `legs` (1 или 2 круга / матча), `criteria` — упорядоченный список критериев (§4), `source` — откуда участники: `entries` (все или выбранные заявки) или `{stage_id, advance}`;
- `round_robin`: только общие;
- `groups`: `group_count`, `advance: {per_group: k, best: [{place: p, count: n}]}`;
- `single_elim`: `third_place: bool`, `two_leg_rounds: [номера раундов]`;
- `double_elim`: `grand_final_reset: bool`;
- `swiss`: `rounds` (по умолчанию ⌈log2 N⌉).

### `stage_draws` — подтверждённые версии жеребьёвки
`stage_id`, `version`, `method` (`pots`, `snake`, `seeded`, `scheme`, `manual`), `seed` (зерно случайности для воспроизводимости), `seeding` (порядок команд по силе), `placement` JSONB (состав групп или расстановка слотов сетки), `confirmed_by`, `confirmed_at`. Версии не переписываются; текущая — с наибольшим номером.

### `fixtures` — пары этапа
| поле | смысл |
|---|---|
| `stage_id`, `draw_id` | этап и версия жеребьёвки, по которой создана пара |
| `group_no`, `round_no` | группа (для групп) и тур/раунд |
| `bracket` | `upper`, `lower`, `final`, `final_reset`, `third`; пусто для круговых |
| `slot` | номер пары в раунде (для сетки) |
| `leg` | 1 или 2 |
| `home_entry_id`, `away_entry_id` | известные команды (могут быть пустыми) |
| `home_source`, `away_source` JSONB | источник: `{"winner": fixture_key}`, `{"loser": …}`, `{"group": "A", "place": 1}`, `{"best": 3, "rank": 1}`, `{"stage_place": n}` |
| `key` | стабильный ключ пары в версии жеребьёвки (`U1-3`, `L2-1`, `G-A-T2-1`) |
| `match_id` | созданный матч; уникален |
| `bye` | пара с пропуском хода, матча не будет |

Изменения в существующих таблицах:
- `tournaments.standings_public bool default true` — показывать общую таблицу турнира без этапов;
- матч не меняется. Связь хранится в `fixtures.match_id`, а при назначении в `stage_label` пишется подпись («Группа A · Тур 2», «1/2 финала»), чтобы рейтинги и существующие экраны работали без правок.

## 4. Правила

### Генерация пар
- **Круговой этап и группы.** Туры строятся круговым методом Бергера. При нечётном числе команд в каждом туре одна команда отдыхает, пара с отдыхом не создаётся. Во втором круге те же туры повторяются с поменянными хозяевами. В групповом этапе так генерируется каждая группа; размеры групп различаются не больше чем на 1.
- **Олимпийка.** Размер сетки — ближайшая степень двойки. Стандартная расстановка сеянных: 1–16, 8–9, 5–12…, так что 1-й и 2-й номера встречаются только в финале. Пропуски хода получают сильнейшие сеянные. По настройке есть матч за 3-е место. В паре из двух матчей первым хозяином принимает слабейший сеянный.
- **Двойное выбывание.** Верхняя сетка как в олимпийке. Проигравшие опускаются в нижнюю по стандартной схеме переходов: в чётных раундах нижней сетки проигравшие верхней встают в обратном порядке, чтобы избежать повторных встреч. Пропуски хода протаскиваются по обеим сеткам. Гранд-финал — один матч; пара `final_reset` создаётся вместе с сеткой, если включена переигровка, но показывается и назначается, только если гранд-финал выиграла команда из нижней сетки.
- **Швейцарская система.** Первый тур: верхняя половина посева против нижней. Каждый следующий тур создаётся командой организатора после подтверждения всех результатов предыдущего. Пары подбираются по группам очков сверху вниз без повторных встреч, перебором с возвратом. Отдых получает самая низкая в таблице команда, которая ещё не отдыхала. Отдых засчитывается как победа: очки за победу, мячи 0:0 не пишутся, в личные встречи не входит.

### Места и критерии
Строка таблицы: игры, победы, ничьи, поражения, забитые, пропущенные, разница, очки. Очки берутся из регламента этапа. Технический результат идёт в зачёт по счёту протокола. Отменённые матчи и матчи без результата не учитываются.

Критерии по умолчанию:
- круговой этап и группы: `points → h2h_points → h2h_goal_diff → h2h_goals → goal_diff → goals_for → wins → lot`;
- швейцарская система: `points → buchholz → goal_diff → goals_for → wins → lot`.

Личные встречи применяются по правилу УЕФА: мини-таблица считается только по матчам между равными командами. Если часть команд разделилась, оставшиеся равные заново проходят личные критерии внутри своей подгруппы, затем общие. `lot` — порядок, который организатор вводит вручную («жребий»). Пока жребий нужен и не введён, таблица показывает равные места и пометку «Нужен жребий», а места, которые от него зависят, не продвигаются дальше.

**Лучшие команды одного места** (например, две лучшие третьих) сравниваются по очкам за матч, затем по разнице за матч, забитым за матч, жребию. Деление на число матчей уравнивает группы разного размера.

### Победитель пары плей-офф
- Один матч: больше мячей по `effective_score`, при равенстве — по `shootout_totals`. Протокол уже не даёт подтвердить ничью, если регламент этапа запрещает ничьи.
- Два матча: сумма мячей двух матчей, гостевой гол не учитывается. При равенстве решает серия пенальти во втором матче. Регламент второго матча должен разрешать ничью и иметь серию пенальти. Если сумма равна, а серии нет, пара показывает «Победитель не определён», и продвижение стоит, пока протокол не исправят.
- Пропуск хода: команда проходит без матча.

## 5. Продвижение и пересчёт

Команды в следующих парах **не сохраняются заранее** — они вычисляются из результатов при каждом чтении:
- в кабинете — по последним подтверждённым версиям протоколов;
- у зрителя — только по опубликованным версиям; неопубликованный результат зритель не видит ни в счёте, ни в продвижении.

Источник `{"group": "A", "place": 1}` разрешается, когда в группе подтверждены все результаты и места не зависят от невведённого жребия. `{"best": 3, "rank": 1}` — когда завершены все группы этапа. `{"stage_place": n}` — когда завершён предыдущий этап.

Назначить дату паре можно, когда обе её команды известны. При назначении команды фиксируются в паре (`home_entry_id`, `away_entry_id`) и в созданном матче. Если позже результат источника изменился и вычисленная команда больше не совпадает с зафиксированной, пара помечается «Результат изменился». Пока у матча нет подтверждённого протокола, организатор может заменить команду одной кнопкой (матч обновляется). После протокола несовпадение остаётся видимым предупреждением, решать его организатору.

Статус этапа вычисляется:
- `draft` — жеребьёвка не подтверждена;
- `drawn` — подтверждена, подтверждённых протоколов нет;
- `started` — есть хотя бы один;
- `completed` — все пары, кроме пропусков, имеют подтверждённый результат и победитель каждой пары определён.

Статус в базе не хранится: `drawn` следует из наличия версии жеребьёвки, остальное — из протоколов.

## 6. Жеребьёвка

Порядок действий у организатора:
1. **Посев.** Список участников этапа выстраивается по силе: перетаскивание на компьютере, кнопки «выше/ниже» на телефоне. Для этапа, который получает команды из предыдущего, посев берётся по его таблице.
2. **Способ.**
   - Группы: «по корзинам» — корзины нарезаются по посеву по `group_count` команд, из каждой корзины в каждую группу случайно попадает одна команда. «Змейкой» — без случайности: 1→A, 2→B, …, затем обратно.
   - Олимпийка и двойное выбывание: «по посеву» (стандартная расстановка) или «случайно».
   - Швейцарская система: первый тур по посеву.
   - Этап, который получает команды из групп: «по схеме». Автосхема ставит победителей групп в разные половины сетки, команды одной группы встречаются как можно позже, места лучших третьих меняются местами между собой, чтобы третья не попала на победителя своей группы.
3. **Предпросмотр.** `preview` ничего не записывает и возвращает состав групп или сетку, все пары и последствия. Кнопка «Перетянуть» даёт новое зерно. Ручная правка — касание двух команд или двух слотов меняет их местами. Корзины видны цветом.
4. **Подтверждение** сохраняет версию `stage_draws` и создаёт пары. Повтор того же запроса возвращает тот же ответ.

**Повторная жеребьёвка** разрешена, пока в этапе нет подтверждённого протокола. Новые пары создаются заново. Матч, назначенный старой паре, переходит к новой паре с теми же командами, тем же туром или раундом и тем же номером матча (сохраняя дату и зал). Остальные такие матчи переводятся в `cancelled`. Предпросмотр заранее показывает: «Сохранятся 3 назначенных матча, 2 будут отменены».

После первого протокола этап закрыт для жеребьёвки. Доступна только замена команды в паре без подтверждённого протокола (например, команда снялась). Замена записывается в пару и в её матч, если он есть.

Смена формата (добавить, удалить или изменить этап) разрешена, пока у этапа нет подтверждённой жеребьёвки. Изменение настроек этапа с жеребьёвкой требует повторной жеребьёвки и подчиняется тем же ограничениям.

## 7. API

Кабинет (`require_admin`, изменения — `require_csrf`, все изменения идемпотентны по `request_id`, правки этапа — по `expected_revision`):

| метод | назначение |
|---|---|
| `GET /tournaments/{tid}/stages` | этапы с настройками, текущей жеребьёвкой, вычисленным статусом |
| `POST /tournaments/{tid}/format` | создать этапы по шаблону (`league`, `groups_playoff`, `playoff`, `double_elim`, `swiss`) с параметрами |
| `POST /tournaments/{tid}/stages`, `PATCH /stages/{sid}`, `DELETE /stages/{sid}` | ручная правка этапов до жеребьёвки |
| `POST /stages/{sid}/draw/preview` | `{method, seed?, seeding, placement?}` → предпросмотр и последствия |
| `POST /stages/{sid}/draw` | `{request_id, expected_revision, method, seed, seeding, placement}` → версия жеребьёвки и пары |
| `POST /stages/{sid}/lots` | `{request_id, group_no, order}` — ввести жребий |
| `POST /stages/{sid}/next-round` | следующий тур швейцарской системы |
| `GET /tournaments/{tid}/fixtures?unscheduled=true` | пары, в том числе без даты |
| `POST /fixtures/{fid}/schedule` | `{request_id, scheduled_at, hall_id, …}` как форма матча без команд и регламента → матч |
| `POST /fixtures/{fid}/replace` | `{request_id, side, entry_id}` — заменить команду |
| `GET /tournaments/{tid}/standings` | таблицы и сетка по подтверждённым протоколам |

Зритель:
- `GET /public/tournaments/{tid}/standings` — таблицы и сетка только по опубликованным протоколам; для турнира без этапов одна общая таблица (`implicit: true`), если `standings_public`;
- `GET /public/tournaments/{tid}/fixtures` — пары без даты по турам и раундам.

Ответ `standings`:
- `stages[]`: `{id, name, kind, status, criteria, groups[], bracket, rounds[]}`;
- `groups[].rows[]`: `{place, team{id,name,logo_id}, played, won, drawn, lost, goals_for, goals_against, goal_diff, points, zone: 'advance'|'best'|null, tied}`;
- `bracket.sections[]`: `{key, rounds[{name, pairs[{key, home, away, legs[{match_id, scheduled_at, status, score}], winner, note}]}]}`, где `home` и `away` — команда или подпись источника («Победитель A», «A1»).

После изменения API экспортируется OpenAPI и обновляется `web/src/api/types.ts`.

## 8. Интерфейс

Общие требования: простой язык без служебных слов (никаких «fixture», «seed», «slot» — «пара», «посев», «место в сетке»); проверка на ширине 375 px без горизонтальной прокрутки страницы; касательные цели не меньше 44 px; светлая и тёмная темы на существующих токенах.

### Организатор
- **Мастер настройки:** шаги «Регламент → Команды → Формат → Жеребьёвка → Проверка».
  - На шаге «Формат» пять карточек-шаблонов с короткой подписью и схемой: «Лига — каждый с каждым», «Группы и плей-офф», «Плей-офф», «Двойное выбывание», «Швейцарская система». После выбора — параметры словами: «4 группы, выходят по 2», «Два круга», «Матч за 3-е место». Ниже этапы карточками, их можно открыть и настроить, в том числе регламент этапа и порядок критериев.
  - Шаг «Жеребьёвка» — §6.
- **Кабинет турнира:** новая вкладка «Таблица» — этапы, таблицы, сетка, жеребьёвка, «Нужен жребий», «Результат изменился», «Следующий тур» для швейцарки. Во вкладке «Матчи» внизу появляется раздел «Без даты»: пары по турам с кнопкой «Назначить». Она открывает форму матча, где команды и регламент уже выбраны и не редактируются.

### Зритель
- В турнире разделы «Таблица · Матчи · Команды · Рейтинги». «Таблица» идёт первой, если у турнира есть этапы или видна общая таблица; иначе первыми остаются «Матчи».
- **Таблица группы:** на телефоне колонки «№, Команда, И, О», касание строки раскрывает В/Н/П и мячи; от 600 px показаны все колонки. Места выхода отмечены полосой слева и подписью внизу «Выходят в плей-офф». Под таблицей одна строка «Места: очки → личные встречи → разница…».
- **Сетка:** на телефоне вкладки раундов («1/4 · 1/2 · Финал»), под ними пары карточками; на широком экране — классическая сетка с линиями. В паре: команды, счёт или дата, «Дата не назначена», победитель выделен. Для двойного выбывания — переключатель «Верхняя · Нижняя · Финал».
- **Швейцарка и лига:** таблица и туры.
- **Пары без даты:** под расписанием блок «Ещё без даты» по турам. Это отдельный компонент; `Schedule.tsx` не меняется, чтобы не пересекаться с PR #19.

## 9. Ошибки и целостность

- Подтверждение жеребьёвки и назначение пары блокируют этап (`SELECT … FOR UPDATE`) и проверяют `expected_revision`; при расхождении — `409` с текущей ревизией, интерфейс предлагает обновить.
- `preview` — чистая функция от `{seed, seeding, placement}`: одно и то же зерно даёт одну и ту же раскладку, подтверждение пересчитывает и сверяет её с присланной расстановкой.
- Ограничения в базе: уникальные `(stage_id, position)`, `(stage_id, version)`, `(draw_id, key, leg)`, `fixtures.match_id`; `home_entry_id != away_entry_id`.
- Сообщения по-русски и по делу: «Жеребьёвку нельзя изменить: в этапе уже есть подтверждённый результат», «Соперник ещё не известен», «Нужен жребий в группе B».
- Архивный турнир закрыт для изменений, как сейчас.

## 10. Проверка

- **Ядро правил** (чистые функции, pytest без базы): круговой метод (каждая пара ровно один или два раза, отдых при нечётном числе, баланс хозяев); олимпийка на 5–16 команд с пропусками; двойное выбывание на 4, 6 и 8 команд (каждая команда выбывает после двух поражений, переигровка только при победе из нижней сетки); швейцарка без повторов на 8 и 9 командах; критерии (круговая ничья трёх команд, разделение подгруппы, жребий); лучшие третьи при группах разного размера; автосхема без встреч одногруппников в первом раунде.
- **API** на `aifootball_test`: идемпотентность подтверждения и назначения; запрет повторной жеребьёвки после протокола; перенос и отмена матчей при повторной жеребьёвке; «Результат изменился»; публичная таблица видит только опубликованные результаты; общая таблица турнира без этапов и её скрытие.
- **Фронтенд:** Vitest для формы формата, предпросмотра жеребьёвки с обменом двух команд, таблицы (раскрытие строки) и сетки (вкладки раундов).
- **E2E (Playwright, база `*_e2e`):** организатор создаёт турнир на 8 команд по шаблону «Группы и плей-офф» → жеребьёвка по корзинам → обмен двух команд → подтверждение → назначение пары → подтверждение и публикация протокола → зритель на 375 px видит таблицу группы и сетку без горизонтальной прокрутки; турнир без формата показывает общую таблицу.
