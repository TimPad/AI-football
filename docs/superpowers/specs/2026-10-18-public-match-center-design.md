# Главная зрителя: календарь матчей с группировкой по турнирам

18 октября 2026. Дополнение к [общему UX/UI-проекту](2026-10-17-tournament-onboarding-and-continuous-ux-design.md). **Предложение; реализация не начата.**

Пользователь просит главную по аналогии с [Sofascore](https://www.sofascore.com/): матчи по календарю, сгруппированные по турнирам, возможно с отдельными элементами ближайших игр. Дополнение: показывать топ рейтинга игроков по турнирам. Главная становится общим расписанием; каталог турниров остаётся доступен дополнительно.

## 1. Основа и границы референса

В официальной странице Sofascore при проверке 18 октября видны текущий день и фильтры All / Live / Finished / Upcoming. Группировка по турнирам и календарь — прямое пожелание пользователя. Конкретные расположение колонок, количество карточек и интервалы ниже — предложения автора плана для AI Football, а не утверждение о точной структуре Sofascore.

Сейчас `PublicHome` в `PublicPages.tsx` показывает вступительный текст и карточки турниров. `Schedule.tsx` уже умеет даты/статусы и строки матчей, но работает в контексте одного турнира. `public.py` возвращает календарь только отдельного турнира. Поэтому новый стартовый экран требует общего публичного запроса, а не загрузки расписания каждого турнира отдельным запросом.

Переиспользуются действующие PublicMatch, опубликованный счёт, логотипы, даты, адресуемое состояние и визуальные токены. Новый многостраничный спортивный портал, новые виды спорта и автоматическая трансляция событий не входят в эту задачу.

## 2. Компоновка

На 1440 px — три области:

| Слева | Основная колонка | Справа |
|---|---|---|
| «Все турниры», поиск/выбор турнира | Выбор даты и календарь | «Ближайшие матчи» — до 3 компактных карточек |
| Доступные турниры | Фильтры статуса, количество найденных матчей | Дата, время, турнир, команды, переход к матчу |
| Ссылка на полный каталог | Заголовок турнира → строки его матчей; затем следующий турнир | При отсутствии ближайших игр блок скрыт |

Ниже ближайших игр в правой колонке — один компактный блок **«Лидеры турнира»** с топ-5 и выбором турнира. Несколько полных таблиц не вытесняют основной календарь. На 1024 px и телефоне рейтинг размещается после основного списка матчей и по умолчанию свёрнут.

Шапка сохраняет бренд и переходы в кабинеты организатора/команды по общему плану. Большой вступительный блок с призывом выбрать турнир уступает место полезному расписанию. Название главного экрана — «Матчи».

На 1024 px — основная колонка плюс компактный выбор турнира; ближайшие игры размещаются под календарём, до основного списка. На 390 px — одна колонка: дата, фильтры, сворачиваемые ближайшие игры, группы матчей. Карточки ближайших игр не должны отодвигать список на несколько экранов; по умолчанию видна одна компактная строка с раскрытием. Горизонтально прокручивается только лента дат, не вся страница.

## 3. Дата и фильтры

- `/` и `/watch` открывают один центр матчей. Без даты в URL выбран **сегодняшний день**, а не день первого турнира.
- Сверху лента на 7 дней вокруг выбранного, стрелки назад/вперёд, «Сегодня» и выбор произвольной даты из календаря. Выбранный день остаётся виден; смена месяца/года работает без перебора дней вручную.
- Фильтры: «Все / Идут / Предстоящие / Завершённые». «Идут» — status live, «Завершённые» — ended, «Предстоящие» — scheduled с началом не раньше серверного now. «Все» также включает отменённые, перенесённые и старые scheduled без результата с явной подписью. Само наступление запланированного времени не переводит матч в «Идут».
- Поиск по названию команды/турнира и выбор турнира работают вместе с датой. Для короткого списка поиск не обязателен на первом экране, но не исчезает уже применённый фильтр.
- Первая версия использует единую зону `Europe/Moscow` и видимую подпись «Время московское». Это решение автора плана для общей ленты: матчи турниров в других зонах переводятся в Москву. Страница отдельного турнира по-прежнему показывает свою зону с явной подписью. Переключатель зоны — последующее улучшение; смешивать зоны в одной ленте нельзя.
- Адрес хранит `day=YYYY-MM-DD`, `status=all|live|upcoming|finished`, `tournament_id`, `team_id`, `q`. Значение all можно не писать. Изменение даты/фильтра сбрасывает только пагинацию; выбранный турнир и поиск сохраняются. Кнопка «Сбросить» очищает фильтры, сохраняя выбранную дату.
- «Сегодня» вычисляется при входе и нажатии по текущему времени, а не по дате сборки. Уже выбранный день не меняется сам в полночь; кнопка «Сегодня» всегда ведёт в актуальный день.
- Закладки и возврат из матча восстанавливают дату, фильтры, раскрытые группы и позицию прокрутки. Отдельные публичные маршруты матча/турнира сохраняются.

## 4. Группы и строки матчей

Каждый турнир — отдельный раскрытый по умолчанию блок. Шапка содержит название/сезон, количество матчей под текущими фильтрами и ссылку «Открыть турнир». Одинаковые названия разных турниров не сливаются: ключ группировки — UUID турнира.

Порядок групп — название без учёта регистра, затем UUID как стабильный ключ; это начальное правило без рекламного приоритета. Внутри группы — время начала, затем UUID. Игры разных залов остаются в одной группе турнира; зал виден в строке и подробнее на странице матча.

Строка: **время/статус → две команды с логотипами → опубликованный счёт либо время начала → зал → значок видео → переход к матчу**. На телефоне команды располагаются друг под другом, счёт справа. Не создавать вложенные интерактивные ссылки: названия команд и действие матча доступны отдельно.

Матч встречается в основном списке ровно один раз. Если он также показан среди ближайших, это явная дополнительная карточка, а не дубликат в календарной группе. Неизвестный результат — «— : —»/«Результат ещё не опубликован», опубликованные 0:0 — настоящий счёт.

«Идут» использует существующий статус организатора. В этой поставке **нет обещания live-счёта или игровой минуты**: число берётся только из опубликованного протокола. У live-матча оно подписано «Опубликованный счёт», чтобы не выдать старый снимок за текущее табло. Перерывы/игровое время не выводятся из приватных часов.

## 5. Отдельные ближайшие игры

Предлагается включить в первую поставку до 3 карточек будущих scheduled-матчей на ближайшие 14 дней. Они сортируются по абсолютному времени начала, затем UUID. Отменённые, перенесённые без актуальной даты и уже прошедшие scheduled-игры не попадают в этот блок; отсчёт берётся от серверного now.

Блок подписан «Ближайшие — от текущего времени». Он независим от выбранной даты/фильтра статуса основного списка, но учитывает выбранный турнир, команду и поиск. Просматривая прошедший день, зритель может отдельно видеть ближайший будущий матч, и смысл этого явно подписан.

В карточке — турнир, дата/время, команды, зал/видео при наличии и переход к матчу. Кнопка «Показать этот день» меняет дату календаря и фильтр статуса на «Все», сохраняя турнир/команду/поиск. Не добавлять отдельный предстоящий матч произвольно из-за его заметности или наличия видео.

## 6. Пустые состояния и обновление

- На выбранную дату нет игр: «18 октября матчей нет», выбранный день сохраняется. Если есть ближайший матч под теми же турнирным/командным фильтрами, предложить перейти к его дню; не переключать календарь автоматически.
- Под фильтром нет игр: показать применённые условия и «Сбросить фильтры» без потери даты.
- Турнир опубликован, но расписание пусто: остаётся доступен через выбор/каталог турниров; не исчезает как сущность.
- Основной список, выбор турнира и ближайшие карточки загружаются с отдельными состояниями. Ошибка ближайших игр не прячет уже доступный календарь; повтор списка не сбрасывает фильтры.
- После смены дня запоздалый ответ предыдущего дня не отображается под новой датой. Во время загрузки показывать skeleton/состояние списка выбранного дня, не его старые матчи.
- В первой поставке данные перечитываются при смене дня/фильтров, возвращении во вкладку и кнопкой «Обновить». Индикатор показывает время успешного получения данных, не время последнего гола. SSE/WebSocket и автоматическое обновление счёта — отдельный этап, требующий публичного live-протокола.

### Лидеры турнира

Предлагается включить в D0 **топ-5 игроков выбранного турнира по действующему опубликованному общему рейтингу**. Место, имя, команда/команды, оценка и число оценённых матчей; имя ведёт в существующую публичную историю игрока, «Весь рейтинг» — во вкладку рейтингов турнира. Фотографии из закрытого каталога не используются.

- Если турнир выбран общим фильтром главной, блок показывает именно его. В режиме «Все турниры» появляется собственный выбор турнира: по умолчанию первая загруженная группа календаря, пользователь может выбрать другой опубликованный турнир из общего каталога. Выбор сохраняется в `leaders_tournament_id` и не меняется при догрузке матчей. Если групп нет и выбор ещё не сделан, показывается приглашение выбрать турнир.
- Глобальный выбор конкретного турнира имеет приоритет над `leaders_tournament_id`; при возврате к «Все турниры» восстанавливается самостоятельный выбор. Поиск команд, фильтр статуса, календарная дата и `team_id` не отбирают игроков рейтинга: подпись **«Рейтинг всего турнира · опубликован …»** объясняет отдельный контекст.
- Между турнирами игроков в один топ не объединять. У каждого свой опубликованный snapshot и база сравнения; сравнение чисел разных турниров на главной не предлагается.
- Порядок, места, равенство баллов и допуск берутся из существующего `get_rankings`/`rank_players`, без нового пересчёта на клиенте. Используется `qualification=qualified`: игрок без оценки или не прошедший текущие пороги методики не попадает в топ. Если подходящих игроков меньше пяти, показать фактическое число, не дополнять предварительными.
- Видна подпись «Пилотный рейтинг», как в существующем продукте. Дата календаря не превращает блок в исторический рейтинг на тот день: он показывает текущую публичную публикацию с её датой. Ссылки фиксируют `snapshot_id`, поэтому переход открывает то же издание, что отображено в блоке.
- Нового расчёта нет: используется текущий public snapshot, даже если администратор уже подготовил новый приватный/неопубликованный. Новая таблица появляется только после явной публикации рейтинга; старое публичное издание сохраняется до неё.
- Нет опубликованного snapshot — «Рейтинг ещё не опубликован». Snapshot есть, но нет qualified-игроков — «Пока недостаточно данных для топа» и переход к полному рейтингу с предварительным списком. Ошибка загрузки имеет отдельный retry и не скрывает матчи/ближайшие.
- Рейтинг загружается одним запросом для выбранного турнира, а не по запросу на каждую группу календаря. Быстрое переключение не подставляет предыдущих лидеров под новое название; на смену лишь дня/статуса не нужен новый расчёт/сброс выбора.

## 7. API и данные

- Новый `GET /public/matches?day=&status=&tournament_id=&team_id=&q=&limit=&cursor=` даёт общий календарь; день фильтруется по `[00:00,00:00 следующего дня)` Europe/Moscow и переводится в UTC на сервере. Day без параметра — текущий московский день.
- Ответ `PublicMatchDayPage{day,timezone,generated_at,items,total,next_cursor,tournament_totals}`; `items` — текущие узкие PublicMatch. `tournament_totals` — словарь UUID→count только для групп, представленных в текущей странице; каждый count считается по всем матчам группы под текущими фильтрами, до применения cursor/limit. Данные закрытых турниров отсутствуют.
- Пагинация серверная: 50 матчей по умолчанию, максимум 100. Сортировка соответствует порядку групп и времени; cursor привязан к day/фильтрам. При продолжении frontend объединяет группу с тем же UUID и не дублирует уже полученные match IDs. Счётчик группы не выдаёт количество загруженной страницы за общее число матчей турнира.
- `GET /public/matches/upcoming?tournament_id=&team_id=&q=&limit=3` возвращает ближайшие scheduled-игры от серверного now на 14 дней, generated_at и зону. Статический маршрут регистрируется до `/public/matches/{mid}`.
- Действующий `/public/tournaments` остаётся каталогом; добавить серверный поиск по названию и пагинацию выбора, а не загружать все турниры/матчи ради клиентской фильтрации.
- Лидеры используют существующий `GET /public/tournaments/{tid}/ratings?qualification=qualified&limit=5&offset=0` без team/position/stage-фильтров. Ответ уже содержит snapshot_id, published_at, label, rank, display_rating, rated_match_count и teams; существующие места не перенумеровываются. Публичная видимость турнира проверяется так же, как в календаре. Отдельного endpoint или расчёта для топа не требуется.
- Используются общий visibility guard из A, текущий match query/projection, PublicMatch и логотипы. Скрытый/архивный турнир не попадает в items, total, group counts, поиск и upcoming. Никаких приватных draft score, контактов капитана, заявок и кадров.
- Общая выдача строится одним запросом/ограниченным числом агрегатных запросов, без запроса на каждый турнир/матч. Новую таблицу под группировку не создавать; нужные индексы добавляются новой миграцией после проверки query plan.

## 8. Поставка и критерии

**D0 — новая главная** становится первой публичной поставкой после A/правил visibility. Она независима от капитанского входа, карт и новых профилей команды/игрока D1. Командные имена до D1 отображаются без неработающих ссылок; матч и турнир кликабельны с D0.

Проверить: сегодня/любой день; два турнира и несколько залов; одинаковые названия с разными UUID; переход через полночь и разные зоны турниров; отмены/переносы; live без опубликованного счёта; честные 0:0; закрытые данные во всех счётчиках; 120 матчей и продолжение одной группы; гонка ответов; пустой день; три ближайшие карточки и независимость от исторической даты; топ-5 строго своего опубликованного турнира, отсутствие рейтинга/допущенных игроков, tied rank и фиксированное издание ссылок; возврат из матча; 1440/1024/390 px и клавиатура.
