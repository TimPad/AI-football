# Подсказки адреса зала — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Подставлять адрес зала из карт во время ввода и сохранять корректную точку с возможностью ручного ввода.

**Architecture:** Общий адресный компонент React получает подсказки через серверный адаптер Яндекса; выбор разрешается в адрес и координаты. Сохранение зала использует существующие request ID, ревизии и снимки, расширенные provenance выбранного адреса.

**Tech Stack:** Текущие FastAPI/Pydantic/SQLAlchemy/Alembic, React/TypeScript, Vitest/Playwright; API Геосаджеста/Геокодера и карта Яндекса по подключённым условиям.

**Spec:** [Сценарий и проверенные источники](../specs/2026-10-17-hall-address-suggest-design.md).

**Статус:** предложение, реализация не начата. Независимое дополнение A1 к основному [плану UX/UI](2026-10-17-tournament-onboarding-and-continuous-ux.md).

## Global Constraints

- Геолокацию браузера не запрашиваем: пользователь вводит город сам.
- Изменение текста после выбора сразу снимает привязку к прежним координатам.
- Для ручного адреса токен и координаты отсутствуют. Старые координаты сохраняются при правке остальных полей зала.
- Правка адреса зала не переписывает уже сохранённые снимки матчей.
- API-ключи и лицензия — зависимости подключения, а не уже настроенный сервис.
- Миграции только новые, зависимости фиксировать в lockfile; тесты только на выделенных БД и синтетических ответах. Не менять общий `web/dist` работающего сервиса.

## Review Focus

1. Ответ старого запроса после нового ввода не заменяет актуальные подсказки — task 2.
2. Изменение адреса не оставляет старую точку; изменение размеров не стирает актуальную точку — tasks 1–2.
3. Timeout/429/отсутствующий ключ не блокирует ручное сохранение — tasks 1–2.
4. Координаты Яндекса не переставлены широта/долгота, клиент не подменяет выбранный URI произвольным URL — task 1.
5. Быстрое создание зала не сбрасывает форму матча и исторические снимки — task 3.

## Task 1: Серверный адресный адаптер и сохранение

**Files:** Create `src/aifootball/service/halls/address_provider.py`, `address_routes.py`, `tests/service/test_hall_addresses.py`; modify `halls/{schemas,models,operations}.py`, `app.py`, `config.py`, `.env.example`; новая Alembic-миграция.

**Interfaces:** `AddressProvider.suggest(query: str) -> list[AddressSuggestion]`, `resolve(uri: str) -> ResolvedAddress`; `GET /halls/address-suggestions?q=`, `POST /halls/address-resolution` с `{suggestion_id}`. Дескриптор подписан сервером и привязан к actor; resolve возвращает address/lat/lon/selection_token. Токен выбора действителен 24 ч; request retry сначала ищет уже сохранённый результат и только затем проверяет срок токена. `HallCreate.address_selection_token: str|None` наследуется HallUpdate как input-only поле и не входит в сохраняемые HallFields/снимки/ответ; `Hall.address_source: manual|yandex`.
