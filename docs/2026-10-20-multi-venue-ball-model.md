# Общая модель мяча для нескольких залов (19–20 октября 2026)

## Зачем

Модель `ball_yaroslavl_v1`, дообученная на одном зале, в другом зале находила 33% мячей вместо 87%
([проверка на другом зале](2026-10-19-new-hall-check.md)). Готовой модели мяча для залов в открытом доступе нет,
готовые веса WASB-SBDT не переносятся. Здесь проверено, что даёт обучение на нескольких залах, новая архитектура
YOLO26 и 260 размеченных кадров нового зала. Все прогоны — `scripts/ball_model_multivenue.py` и
`scripts/eval_ball_multivenue.py`; данные, веса и результаты вне Git.

## Данные

- **Старый зал** (Ярославль 2020, камера в углу): 570 вырезок обучения v1 (35:00–45:00).
- **Roboflow, CC BY 4.0**, скачал пользователь: Futsal Ball Detection v3 (в основном уличные поля с неподвижной
  широкоугольной камерой, один зал; мяч ~12 px) и Pro futsal detection v8 (много залов, в основном трансляции; ~9 px).
  Из обоих взят только класс «мяч».
- Всё приведено к вырезкам 640 × 640 в исходном разрешении (мяч сохраняет размер в пикселях), рамка мяча не меньше
  32 px, как у v1: на 10-пиксельной рамке `cls_loss` уходил в NaN. Набор v1: 6896 вырезок обучения, 1380 проверки.
- **Новый зал** (Ярославль 2023, камера за воротами) в набор v1 не входит: на нём проверка. Его эталоны —
  мяч на 200 кадрах 7:00–10:00 и журналы касаний 7:00–10:00 и 20:00–23:00 — не входят ни в одно обучение.
- **Третий зал** — Кострома (720p, оранжевый мяч на оранжевом полу, ~1 Мбит/с) — только для проверки, мяч на 200 кадрах.

## Модель на кадрах эталона

Тот же путь, что в пайплайне (`BallDetector`: закрашенный кадр, вырезки 1280), метрики `cli eval-ball`, порог 0,25:

| Модель | Старый зал: найдено / самая уверенная — мяч | Новый зал | Ложные в кадрах без мяча (новый) | Кострома |
|---|---|---|---|---|
| v1, только старый зал | 87% / 0,93 | 38% / 0,36 | — | 0% |
| YOLO11s, старый зал + Roboflow, эпоха 20 | 85% / 0,85 | 52% / 0,45 | 24/42 | 5% / 0,09 |
| YOLO26s, тот же набор, 30 эпох | 89% / 0,87 | 77% / 0,46 | 40/42 | 29% / 0,18 |
| **YOLO26s + 260 кадров нового зала** | **88% / 0,93** | **82% / 0,79** | **15/42** | 32% / 0,22 |

- YOLO26s не тяжелее YOLO11s (10,0 против 9,5 млн параметров, 22,8 против 21,7 GFLOPs), обучается тем же рецептом
  (AdamW, без смешанной точности, без разгона сдвига), но находит намного больше мячей в чужом зале.
- Почти все ложные YOLO26 без кадров нового зала — одна точка: рука зрителя, облокотившегося на бортик, минутами на
  месте. Правило «неподвижный мяч» (кандидат в одной точке ±15 px больше половины кадров в окне ±10 с) их снимает и в
  старом зале ничего не теряет. После добавления кадров нового зала модель руку за мяч больше не принимает, и правило
  ничего не меняет.
- Ultralytics выбирает «лучшую» эпоху по mAP50-95, а у рамок, искусственно увеличенных до 32 px, эта метрика скачет
  на ±0,1 между эпохами. Брать веса последней эпохи: у YOLO11 «лучшая» 12-я в старом зале давала 76% против 85%.
- Кострома не переносится ни одной моделью: кадры нового зала на чужой зал не повлияли.

## Как выбирать мяч из кандидатов

Один мяч на кадр, как в пайплайне: самый уверенный от 0,25 и отсев скачков > 25 м/с. На кадрах эталона
(«точность» — доля кадров с выбранным мячом, где он верный, включая кадры без мяча):

| Модель | Старый зал | Новый зал |
|---|---|---|
| v1 | 78% / 0,96 | 20% / 0,45 |
| v1 + «не на торсе» | 75% / 0,98 | 21% / 0,59 |
| YOLO11s, эпоха 20 + «не на торсе» | 76% / 0,95 | 41% / 0,78 |
| YOLO26s + «неподвижный мяч» | 82% / 0,95 | 56% / 0,78 |
| **YOLO26s + новый зал** | **82% / 0,96** | **74% / 0,88** |
| YOLO26s + новый зал + «не на торсе» | 79% / 0,98 | 65% / 0,92 |

Проверены и не помогли: траектория одного мяча по кандидатам (граф по кадрам со скоростью ≤ 25 м/с) — в кадрах без мяча
строит путь по ложным на игроках; модель старого зала на кадре, уменьшенном вдвое.

## Передачи по журналам

Игроки и треки из готовых прогонов, заменён только мяч; передача засчитана, если та же команда и приём ±1 с.

| Мяч | Новый зал, F1 (найдено / верных из найденных) | Старый зал, F1 |
|---|---|---|
| v1 / v2 (своя модель старого зала) | 0,22 (10/64, 10/29) | **0,69** (34/57, 34/42) |
| YOLO11s, эпоха 20 + «не на торсе» | 0,40 (20/64, 20/37) | 0,62 |
| YOLO26s + «неподвижный мяч» + «не на торсе» | 0,47 (25/64, 25/43) | 0,65 |
| **YOLO26s + новый зал** | **0,48** (23/64, 23/32) | 0,58 |

- В новом зале команда у мяча совпадает с журналом в 37% игрового времени (было 19%), доля владения синих на
  20:00–23:00 — 66% при 67% по журналу (было 45%). Остановки от модели мяча почти не зависят.
- В старом зале v2 по передачам лучше, хотя на кадрах эталона новая модель не хуже: проигрыш на 10:00–13:00 (7 из 21
  против 10), а эталона мяча на этом фрагменте нет.

## Почему не найдена 41 передача нового зала

`eval_ball_multivenue.py missed` — первое порвавшееся звено у момента приёма по журналу:

| Звено | Передач |
|---|---|
| Владелец не сменился: пас короткий, отдающий держит мяч, пока он в 2,5 м | 11 |
| Отдал (9) или принял (5) игрок другой команды | 14 |
| Владелец назначен на 1,5–2,5 с позже (4) или мяч ничей дольше 3 с (3) | 7 |
| Выпала внутри найденной остановки | 3 |
| Пауза владения > 3 с (2), нет предыдущего владельца (2), засчитано ударом (1), мяч далеко от игроков (1) | 6 |

Мяч у приёма есть во всех 41 случаях: узкое место передач теперь — правила владения (подобраны по старому залу при
15 к/с: удержание 2,5 м, захват 1,8 м, подтверждение 0,33 с) и команды треков, а не детектор мяча.

## Что включено

- Новый зал переключён на модель `ball_multi_y26_hall2` (`data/venues/yaroslavl2`, порог 0,25; вне Git), мяч в его
  прогонах заменён (`ball_model_multivenue.py replace`, прежний файл сохранён рядом). Старый зал остаётся на своей модели.
- Исправлено `perception/ball_detect.cover_tiles`: при кадре меньше вырезки (720p, 1080p) вырезка уходила за край, и
  своя модель мяча не находила мяч вовсе. На Костроме из-за этого все модели сначала показали 0.
- `tools.label_ball --hints`: подсказка модели на кадре, Enter её принимает. На 260 кадрах нового зала приняты как
  есть 68 из 94 подсказок; ошибалась модель на зрителях у ближнего бортика.

## Ограничения

- После добавления кадров новый зал — уже не проверка «без дообучения»; честный перенос показывает только Кострома.
- Один матч на зал, по 3 минуты на фрагмент; 57 и 64 передачи. Разница в 2–4 передачи — в пределах шума.
- «Неподвижный мяч» и «не на торсе» в пайплайн не включены: с моделью, видевшей зал, первое не нужно, второе
  помогает только старому залу.

## Воспроизвести

```sh
S=scripts/ball_model_multivenue.py; E=scripts/eval_ball_multivenue.py
.venv/bin/python $S crops --source old data/datasets/yaroslavl-ball-v1 --source rf3 <Futsal Ball Detection v3> \
  --source pro <Pro futsal detection v8> --out data/datasets/ball-multi-v1
.venv/bin/python $S train --data data/datasets/ball-multi-v1/data.yaml --base yolo26s.pt --out output/ball-multi/v26
.venv/bin/python $S candidates --weights <веса> --video <обучающий отрезок> --venue data/venues/yaroslavl2 --out <кандидаты>
.venv/bin/python $S labeling --candidates <кандидаты> --venue data/venues/yaroslavl2 --out data/gt/yaroslavl2-2100-2280
.venv/bin/python -m aifootball.tools.label_ball ... --frames data/gt/yaroslavl2-2100-2280/frames.txt --hints data/gt/yaroslavl2-2100-2280/hints.parquet
.venv/bin/python -m aifootball.tools.ball_dataset ... --tile 640 --min-box 32 --out data/datasets/yaroslavl2-ball-tiles
.venv/bin/python $S add-hall --base data/datasets/ball-multi-v1 --tiles data/datasets/yaroslavl2-ball-tiles --tag yar2 ... --out data/datasets/ball-multi-v2
.venv/bin/python $E frames|select|passes|missed ...   # аргументы — в справке скрипта
```

Обучение на M2 Pro: ~8–10 мин на эпоху, 30 эпох ≈ 4 ч; продолжить после остановки —
`YOLO('<папка>/weights/last.pt').train(resume=True)` (Ultralytics продолжает с последней сохранённой эпохи).
